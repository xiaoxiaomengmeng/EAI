## 一、π₀.₅ 与 π₀ 的关键差异（先读）

很多人会把 π₀.₅ 当成 π₀ 的"小升级"，其实它俩是**同一 PaliGemma 骨干、不同方法论**的两代模型。下面这张表是后续所有命令差异的根源，先理解再动手。

### 1.1 架构差异表（lerobot 官方对比）

| 维度 | π₀ | π₀.₅ |
|------|------|------|
| **骨干** | PaliGemma 2B + Gemma Expert 300M | PaliGemma 2B + Gemma Expert 300M（**相同**） |
| **参数总量** | ~3.3B | ~3.3B（**基本一致**，π₀.₅ 略低，因无 state embedding） |
| **时间条件** | 时间 token 与动作 token **拼接**（`action_time_mlp_*`） | 时间用 `time_mlp_*` 做 **AdaRMS 条件**（自适应归一化） |
| **AdaRMS** | 不用 | action expert 内启用 |
| **Tokenizer 长度** | 48 tokens | **200 tokens** |
| **State 输入方式** | 连续 state 经 `state_proj` 投影成 1 个 token | **离散化**为 256 bin，写入 prompt（无 state_proj） |
| **State embedding** | 有 | 无（所以参数略低） |
| **Action 生成** | Flow Matching 10 步去噪 | Flow Matching 10 步去噪（**相同**） |
| **chunk_size / n_action_steps** | 50 / 50 | 50 / 50（默认相同，可调） |
| **License** | Gemma License（商用受限） | **Apache 2.0**（商用友好） |

### 1.2 训练方法论差异（π₀.₅ 的核心创新）

π₀.₅ 相比 π₀ 最大的进步不在架构（架构基本一致），而在**训练数据与方法论**：

1. **六类异构数据联合训练（Co-Training）**：π₀ 主要在跨本体机器人数据上训练；π₀.₅ 在六类异构数据上联合训练：
   - 多模态网络数据（image captioning、VQA、object detection）
   - Verbal Instructions（人类逐步语音指导）
   - Subtask Commands（高级语义子任务标签，如 "pick up the pillow"）
   - Cross-Embodiment Robot Data（跨本体机器人数据）
   - Multi-Environment Data（静态机器人部署到多个家庭）
   - **Mobile Manipulation Data：~400 小时**移动机器人演示，覆盖 **~100 个家庭**
2. **Knowledge Insulation（知识隔离）**：VLM 主干用 FAST 离散化动作学习高质量表征，action expert 同时适配连续动作但**不回传梯度到 VLM 主干**，避免破坏预训练知识。这正是 π₀.₅ 能泛化到全新环境而不丢失基础能力的关键。
3. **分层推理（Hierarchical Inference）**：π₀.₅ 在原始论文中先预测高层子任务文本，再生成底层动作。**注意：lerobot 仓库的 pi05 实现**只复刻了 flow matching head，**未实现子任务预测**（[openpi README 原文](https://github.com/Physical-Intelligence/openpi)：*"in this repository, we currently only support the flow matching head for both π0.5 training and inference"*）。所以 lerobot 里的 pi05 ≈ π₀ 的"换皮 + AdaRMS + 离散 state + 200 token"，**没有论文里那套分层推理**。

### 1.3 能力差异（为什么值得用 π₀.₅）

- **π₀**：跨本体 / 跨任务泛化（同一个模型跑不同机器人、不同任务）
- **π₀.₅**：在 π₀ 基础上进一步做**开放世界泛化（open-world generalization）**——在从未见过的家庭中完成 10-15 分钟的多阶段任务（清洁厨房、整理卧室）
- **License 友好**：Apache 2.0 让 π₀.₅ 在商用场景上比 π₀（Gemma License）自由得多

### 1.4 在 lerobot v0.6.2 中的支持情况

| 项 | π₀ | π₀.₅ |
|------|------|------|
| `policy.type` | `pi0` | `pi05` |
| 默认归一化 | MEAN_STD | **QUANTILES**（需数据集有 q01/q99） |
| 配置文件 | `policies/pi0/configuration_pi0.py` | `policies/pi05/configuration_pi05.py` |
| 默认 pretrained 基座 | `lerobot/pi0_base` | `lerobot/pi05_base`（或 `lerobot/pi05_libero_base`） |
| 是否支持 LoRA | ✅ | ✅ |
| 是否支持 `train_expert_only` | ✅ | ✅ |
| 是否支持 `freeze_vision_encoder` | ✅ | ✅ |
| 是否支持 EMA | ❌（v0.6.2 源码未暴露开关） | ✅ `--ema.enable=true --ema.decay=0.99` |
| 是否支持相对动作 | ❌ | ✅ `--policy.use_relative_actions=true` |
| 是否支持 MEM 短时记忆 | ❌ | ✅ `--policy.use_visual_memory=true`（默认关） |

> 一句话总结：**架构上 π₀.₅ ≈ π₀ 换皮（同骨干、同 flow matching），方法论上 π₀.₅ ≫ π₀（异构数据 + 知识隔离 + 开放世界泛化），License 上 π₀.₅ ≫ π₀（Apache 2.0 vs Gemma）。lerobot 里的 pi05 是 π₀.₅ 的"flow matching head only"简化版，但已经包含 AdaRMS + 离散 state + 200 token 这些核心架构改进。**

> **为什么仍需 `HF_HUB_OFFLINE=1` 这套 trick？**
> π₀ 文档里踩过的大坑是 paligemma tokenizer 必须从 HF 拉 `google/paligemma-3b-pt-224`（gated 仓库，国内 403）。π₀.₅ 用的是同一个 tokenizer（pi05 的 `processor_pi05.py` 也硬编码 `google/paligemma-3b-pt-224`），所以**这个问题完全没变**——你**复用 π₀ 文档里已经做好的 HF 缓存注入 trick 即可**（17 号文档第八节排错表里那条，scripts/train_pi0.sh 已内置 `HF_HUB_OFFLINE=1`）。pi05 训练脚本也要带这个环境变量。

### 4.6 Quantile 统计问题（π₀.₅ 最大的坑，所有路线必读）

π₀.₅ 默认用 `QUANTILES` 归一化 STATE 和 ACTION（见 `configuration_pi05.py` L87-93 的 `normalization_mapping` 默认值），要求数据集 `meta/stats.json` 里有 `q01` 和 `q99` 字段。

**本机实测**（2026-08-23）：

```bash
# aloha 数据集 meta/stats.json 里 grep 'q01|q99|quantile' → 无匹配
# 即 aloha 数据集只有 min/max/mean/std，没有 quantile 统计
```

LIBERO 数据集的 stats.json 是否有 quantile 统计，下载后用同样方法 grep 确认。若也没有，按下面任一方案处理：

**方案 1（最简单，推荐）**：传 `--policy.normalization_mapping` 改用 MEAN_STD，**完全不动数据集**：

```bash
--policy.normalization_mapping='{"ACTION": "MEAN_STD", "STATE": "MEAN_STD", "VISUAL": "IDENTITY"}'
```

> 这是 lerobot 官方 LIBERO 训练示例采用的方案（pi05.mdx L102 原文：*"Mean/std normalization, not π₀.₅'s quantile default — matching pi05_libero_finetuned_v044"*）。官方 benchmark 复现也是用 MEAN_STD 跑的。

**方案 2（标准做法，统计更鲁棒）**：用 `lerobot-edit-dataset` 给数据集补 quantile 统计：

```bash
lerobot-edit-dataset \
    --repo_id aloha_sim_transfer_cube_human \
    --new_repo_id aloha_sim_transfer_cube_human \
    --operation.type recompute_stats \
    --operation.overwrite true
```

> 注意：结果会写到 `$HF_LEROBOT_HOME/your_dataset`，**不是原数据集目录**。所以训练时要么用 `--dataset.root=$HF_LEROBOT_HOME/your_dataset` 指向新位置，要么加 `--push_to_hub true` 上传。这条路比方案 1 麻烦，**本文档默认走方案 1**。

**方案 3（精确 quantile，openpi 风格）**：用 lerobot 的 `augment_dataset_quantile_stats.py` 做直方图估算：

```bash
python ~/ws/101-pi-serial-models/repos/lerobot-main/src/lerobot/scripts/augment_dataset_quantile_stats.py \
    --repo-id=aloha_sim_transfer_cube_human \
    --overwrite \
    --skip-images
```

> 这是 openpi 原版的精确 quantile 估算方式，但 histogram 估算有 discretization 误差，loss 量级会变。**不推荐第一次跑用**。

## 五、微调训练

### 5.1 显存预算决策表（RTX 5090 = 32GB）

π₀.₅ 共约 3.3B 参数，与 π₀ 同量级。显存估算（与 π₀ 文档表基本一致）：

| 训练模式 | 可训练参数 | 显存估算 | 5090（32GB） |
|----------|-----------|----------|--------------|
| 全参数微调（AdamW + bf16） | 3.3B | ≈ 50-70GB | ❌ 不可行 |
| 全参数 + gradient_checkpointing + batch 1-2 | 3.3B | ≈ 25-30GB | ⚠️ 勉强，易 OOM |
| **仅训练 Action Expert**（`train_expert_only=true`，冻结 VLM） | 300M | ≈ 14-18GB | ✅ 备选 |
| **LoRA 微调**（peft） | ~1-5% | ≈ 12-18GB | ✅ 推荐首选 |
| **freeze_vision_encoder=true**（只冻结视觉编码器） | ~3B | ≈ 30-40GB | ⚠️ 紧张 |

> **推荐策略**：32GB 显存首选 LoRA（与 π₀ 一致）；备选 `--policy.train_expert_only=true`（冻结 VLM，只训 action expert + projections，省显存且效果在 50 条演示的小数据上通常与 LoRA 接近）。

### 5.2 路线 A：在 ALOHA 真实数据集上训练（aloha_static_cups_open，推荐！）

封装为 `scripts/train_pi05_aloha_static.sh`（⏳ 待创建，参数已按 v0.6.2 pi05.mdx + 实测 config 核对）：

```bash
lerobot-train \
  --dataset.repo_id=aloha_static_cups_open \
  --dataset.root=~/ws/101-pi-serial-models/data/aloha_static_cups_open \
  --output_dir=~/ws/101-pi-serial-models/outputs/pi05_aloha_static \
  --job_name=pi05_aloha_static \
  --policy.type=pi05 \
  --policy.pretrained_path=~/ws/models/pi05_base \
  --policy.dtype=bfloat16 \
  --policy.device=cuda \
  --policy.push_to_hub=false \
  --policy.normalization_mapping='{"ACTION": "MEAN_STD", "STATE": "MEAN_STD", "VISUAL": "IDENTITY"}' \
  --policy.gradient_checkpointing=true \
  --rename_map='{"observation.images.cam_high":"observation.images.base_0_rgb","observation.images.cam_left_wrist":"observation.images.left_wrist_0_rgb","observation.images.cam_right_wrist":"observation.images.right_wrist_0_rgb"}' \
  --peft.method_type=LORA \
  --peft.r=16 \
  --wandb.enable=false \
  --steps=20000 \
  --batch_size=4
```

**这条命令的关键点**：
- **不需要 `--policy.empty_cameras`**：aloha_static 数据集有 4 个相机，rename 后正好填满 pi05_base 期望的 3 个相机槽位（`base_0_rgb` + `left_wrist_0_rgb` + `right_wrist_0_rgb`），第 4 个 `cam_low` 不传给模型（lerobot 自动忽略未在 `--rename_map` 中的相机）
- **`--rename_map` 是三键映射 JSON**：注意 shell 单引号包裹整个 JSON 字符串
- **`--policy.normalization_mapping` 必传**：绕开 quantile 坑（aloha_static 数据集无 q01/q99，需实测确认）
- **`--policy.gradient_checkpointing=true`**：pi05.mdx 标配，省显存
- **预先检查**：先跑 4.5 节方式 1 的 `LeRobotDataset` 加载测试，确认 v2.0 → v0.6.2 兼容性；若报 `codebase_version` 不匹配，先按方式 2 转换数据集

### 5.3 路线 B：在 LIBERO 上训练（80GB GPU 官方示例 + 5090 适配）

官方 pi05.mdx 给的命令是为 80GB GPU 设计的（batch 64、30000 步），5090 32GB 要降配：

### 5.5 与 π₀ 训练命令的差异（路线 C 对比，逐项核对）

| 参数 | π₀ | π₀.₅ | 说明 |
|------|------|------|------|
| `--policy.type` | `pi0` | **`pi05`** | 核心差异 |
| `--policy.pretrained_path` | `models/pi0_base` | **`models/pi05_base`** | 换基座 |
| `--policy.normalization_mapping` | 不传（默认 MEAN_STD） | **必传**（绕开 quantiles 坑） | π₀.₅ 默认 QUANTILES，aloha 数据无 q01/q99 |
| `--policy.empty_cameras` | 不传（π₀ 基座只期望 1 个相机） | **`2`**（pi05_base 期望 3 个相机：base_0_rgb + left_wrist_0_rgb + right_wrist_0_rgb，aloha 只有 top→base_0_rgb 1 个，需补 2 个空槽） | 实测 pi05_base config 确认（见第三节 config.json） |
| `--policy.gradient_checkpointing` | `false`（LoRA 显存充裕） | **`true`**（pi05 官方示例标配） | pi05.mdx 推荐 |
| `--rename_map` | 必传 | 必传（**ALOHA 路线必传**；LIBERO 路线不传） | 相机键名对齐 |
| `--peft.method_type` + `--peft.r` | LORA + r=16 | LORA + r=16 | 一致 |
| `--steps` / `--batch_size` | 20000 / 4 | 20000 / 4 | 一致 |

> ⚠️ `--policy.empty_cameras=2` 是 ALOHA **仿真**路线（路线 C）的另一个坑：pi05_base 的 config 实测期望 3 个相机（`base_0_rgb` + `left_wrist_0_rgb` + `right_wrist_0_rgb`），而 ALOHA 仿真只有 `top` 1 个相机，rename 后还差 2 个槽位——必须用 `empty_cameras=2` 补齐，否则会报相机数不匹配。对比 LIBERO 路线只需 `empty_cameras=1`（LIBERO 有 2 个相机，差 1 个）。**路线 A（aloha_static_cups_open）无需此参数**——4 个相机选 3 个 rename 后完美匹配 pi05_base。

### 6.3 安装 LIBERO 仿真 assets（路线 B 评估必装，实测 2026-08-28）

**现象（首次评估必踩的坑）**：`lerobot-eval` 启动 libero env 时，第一个 episode reset() 会报：
```
FileNotFoundError: [Errno 2] No such file or directory:
  '.../libero/libero/assets/scenes/libero_tabletop_base_style.xml'
```
此前的 warning 线索：
```
Local assets not found. Downloading from HuggingFace Hub...
Failed to download assets from lerobot/libero-assets: Cannot find an appropriate cached snapshot folder
... outgoing traffic has been disabled. To enable repo look-ups and downloads online, set 'HF_HUB_OFFLINE=0'
```

#### 根因

`hf-libero` 包**不捆绑仿真场景资源**（robosuite Mujoco 场景 XML / STL / 纹理约 587 个文件）。`libero/libero/__init__.py` 的 `get_assets_path()` 搜索优先级：
1. **venv 本地路径** `site-packages/libero/libero/assets/`（默认不存在，所以不命中）
2. **HuggingFace Hub** `snapshot_download(repo_id="lerobot/libero-assets", repo_type="dataset")`（训练/评估脚本设置了 `HF_HUB_OFFLINE=1` 离线模式，**被直接阻挡**）
3. 回退到 venv 路径（仍不存在 → FileNotFoundError）

国内无法直连 HuggingFace，且 `HF_HUB_OFFLINE=1` 必须保留（paligemma tokenizer 离线），所以**正确做法：从 ModelScope 下 `lerobot/libero-assets` 数据集**，然后**让 venv 本地路径存在**。

#### 正确安装步骤（✅ 实测 2026-08-28）

```bash
source ~/ws/101-pi-serial-models/.venv312/bin/activate

# 1. 从 ModelScope 下载 lerobot/libero-assets（HF dataset，ModelScope 同步）
#    → 587 个文件，含 scenes / articulated_objects / stable_scanned_objects / textures / turbosquid_objects 等
#    → 约 1 分 51 秒下完
mkdir -p ~/.libero
modelscope download --dataset lerobot/libero-assets --local_dir ~/.libero/assets
# ✓ Snapshot ready at /home/creator/.libero/assets

# 2. 在 venv 的 libero/libero/ 目录下建 assets 软链（使 libero/__init__.py 优先命中本地，不走 HF 下载）
#    （否则即使 ~/.libero/assets 存在，get_assets_path() 也只会查 venv 路径或 HF，不查 ~/.libero/assets）
LIBERO_VENV_PATH="$HOME/ws/101-pi-serial-models/.venv312/lib/python3.12/site-packages/libero/libero"
ln -sfn ~/.libero/assets "$LIBERO_VENV_PATH/assets"

# 3. 更新 ~/.libero/config.yaml（libero 会读，保证 benchmark 等辅助工具也找到）

cat > ~/.libero/config.yaml <<EOF
assets: $HOME/.libero/assets
bddl_files: $LIBERO_BENCHMARK_ROOT/bddl_files
benchmark_root: $LIBERO_BENCHMARK_ROOT
datasets: $LIBERO_BENCHMARK_ROOT/../datasets
init_states: $LIBERO_BENCHMARK_ROOT/init_files
EOF

# 4. 验证 get_assets_path() 返回本地（不走 HF）
python3 -c "
import os
os.environ['HF_HUB_OFFLINE'] = '1'
from libero.libero import get_assets_path
p = get_assets_path()
print('get_assets_path() =', p)
print('libero_tabletop_base_style.xml exist:',
      os.path.exists(os.path.join(p, 'scenes/libero_tabletop_base_style.xml')))
"
# 预期输出：
#   get_assets_path() = .../site-packages/libero/libero/assets  ← 走软链，不是 HF
#   libero_tabletop_base_style.xml exist: True
```

> **自动化**：`scripts/train_pi05_libero.sh` 和 `scripts/eval_pi05_libero.sh` 开头已内置同款 `ensure_libero_assets()` 自检函数——若 venv assets 软链缺失，会自动把 `~/.libero/assets` 软链过去；若两者都缺则报 actionable 错误提示（modelscope download 命令），**不会再出现 FileNotFoundError + 无修复指引的情况**。

## 七、推理与 Rollout 评估

### 7.1 三条路线的评估能力对比（先看清自己能评什么）

| 路线 | 训练 | Rollout 评估 | 评估方式 |
|------|------|-------------|----------|
| A：aloha_static_cups_open | ✅ | ❌ **无对应仿真环境**（真实世界数据集，没配套 sim env） | 只能看训练 loss 曲线判断学没学会；想真机部署需 ALOHA 机器人 |
| B：LIBERO | ✅ | ✅ 4 个子集 × 50 轮 | 对标官方 97.5% benchmark |
| C：aloha_sim_transfer_cube_human | ✅ | ✅ ALoHa 仿真 25 轮 | 对比 π₀ 16% 成功率 |

> **重要权衡**：路线 A（aloha_static_cups_open）能充分利用 pi05 双腕预训练能力，但**无法在仿真环境 rollout 验证**——它来自真实 ALOHA 机器人采集，没有配套的 gym 环境。所以路线 A 适合**训练 loss 对比研究**，但无法给你"成功率"这个硬指标。如果你想要成功率，要么走路线 B（LIBERO benchmark），要么走路线 C（aloha_sim 与 π₀ 16% 对比）。

### 7.2 路线 C：ALOHA 仿真 rollout 评估（与 π₀ 文档同环境）

```bash
lerobot-eval \
  --policy.path=~/ws/101-pi-serial-models/outputs/pi05_aloha_sim/checkpoints/last/pretrained_model \
  --env.type=aloha \
  --env.task=AlohaTransferCube-v0 \
  --eval.n_episodes=25 \
  --rename_map='{"observation.images.top":"observation.images.base_0_rgb"}'
```

> 与 π₀ 评估命令的**唯一差异**：`--policy.path` 指向 pi05 训练出来的 checkpoint 目录（自动识别为 pi05 类型）。其他参数（`--env.type=aloha`、`--env.task=AlohaTransferCube-v0`、`--eval.n_episodes=25`、`--rename_map`）**完全一致**。

### 7.3 路线 B：LIBERO 评估（参考官方 benchmark）

LIBERO 评估有 4 个子集（Spatial / Object / Goal / 10），每个子集独立评估。官方复现结果（pi05.mdx L326-332）：

|-----------|-------------|-------------|
| Libero Spatial | 97.0% | 98.8% |
| Libero Object | 99.0% | 98.2% |
| Libero Goal | 98.0% | 98.0% |
| Libero 10 | 96.0% | 92.4% |
| **Average** | **97.5%** | **96.85%** |

> 这是用 `lerobot/pi05_libero_base` + 6k 步额外微调后的结果。5090 机从 `pi05_libero_base` 起步 + 30k 步 LoRA 训练，能跑到什么程度，**待实测回填**。

#### 7.3.1 单子集评估命令（封装为 `scripts/eval_pi05_libero.sh` ✅）

## 八、排错速查表（π₀.₅ 专属新增项 + π₀ 已知项）

| 症状 | 原因 | 解决 |
|------|------|------|
| `ValueError: QUANTILES normalization mode requires q01 and q99 stats` | π₀.₅ 默认用 QUANTILES 归一化，数据集 `meta/stats.json` 无 `q01`/`q99` | 传 `--policy.normalization_mapping='{"ACTION": "MEAN_STD", "STATE": "MEAN_STD", "VISUAL": "IDENTITY"}'`（最简）；或用 `lerobot-edit-dataset --operation.type recompute_stats` 补统计 |
| `AttributeError: ... PI05Policy ...` 或 `policy.type=pi05` 不识别 | lerobot main 版本过旧，无 pi05 模块 | 升级 lerobot main 到 v0.5.0+（实测 v0.6.2 自带）；`python -c "from lerobot.policies.pi05.modeling_pi05 import PI05Policy"` 验证 |
| `paligemma tokenizer` 超时 / 403 | pi05 用同一个 `google/paligemma-3b-pt-224` gated tokenizer | **复用 π₀ 文档第八节那条 trick**：从 ModelScope 拉 tokenizer 注入 HF 缓存 + `export HF_HUB_OFFLINE=1` |
| **lerobot[libero] 安装失败：`egl_probe` 编译报 `Command '['cmake', '--version']' returned non-zero exit status 1`**（实测 2026-08-23） | **pip build isolation 环境 PATH 中找不到 cmake**——venv312 已装 cmake 4.1.3 wheel，但隔离环境不复用 venv 的 PATH | 加 `--no-build-isolation` 让 pip 直接用 venv 环境：`pip install -e ".[libero]" --no-build-isolation` |
| **加 `--no-build-isolation` 后 egl_probe 仍报 `Command 'cmake ..; make -j' returned non-zero exit status 2`**（实测） | **egl_probe 的 `CMakeLists.txt` 第 1 行写 `cmake_minimum_required(VERSION 2.8.12)`**，但 venv312 装的 cmake 是 **4.1.3**（pip wheel），**cmake 4.x 移除了对 < 3.5 最低版本的兼容**，configure 阶段直接报错 | **临时卸载 venv 的 cmake wheel，让系统 cmake 3.22.1 接管**：`pip uninstall cmake -y && pip install -e ".[libero]" --no-build-isolation`。装完 pip 会自动把 cmake 4.1.3 wheel 装回，但 `egl_probe` 的 wheel 已缓存到 `~/.cache/pip/wheels/`，下次重装直接用 wheel 不再编译。**根因**：lerobot issue #3111 和 #3397 已知 bug，`hf-egl-probe` 是 HuggingFace 的修复 fork（兼容 cmake 4.x），但 `egl_probe` 原版未修；hf-libero 同时依赖两者 |
| `import hf_libero` 失败 `ModuleNotFoundError` | PyPI 包名 `hf-libero` ≠ Python 模块名，**实际模块名是 `libero`** | 改用 `import libero` 或 `from libero.libero import benchmark` |
| 训练启动即 CUDA OOM | batch 太大或开了 `freeze_vision_encoder=false` + `train_expert_only=false` | batch 降到 1-2；开 `--policy.train_expert_only=true`；开 `--policy.gradient_checkpointing=true` |
| LIBERO 训练 `n_action_steps` 被 reset 到 50 | `--policy.pretrained_path` 只加载权重不加载 config，`n_action_steps` 走默认值 | 显式传 `--policy.n_action_steps=10`（pi05.mdx L104 原文） |
| LIBERO 训练相机数不匹配 | pi05_base 期望 3 个相机，LIBERO 只有 2 个 | 传 `--policy.empty_cameras=1` 补一个空相机槽 |
| 相对动作训练报错 | 没先用 `lerobot-edit-dataset --operation.relative_action true` 重算 stats | 先按 pi05.mdx Relative Actions 章节重算 stats，再传 `--policy.use_relative_actions=true` |
| 全参数微调 OOM | π₀.₅ ~3.3B，全参 AdamW 需 50-70GB | 改 LoRA 或 `--policy.train_expert_only=true` |
| 模型加载阶段 OOM | F32 权重直接载入（pi05_base 实测 14GB F32，与 π₀ 同等大小） | 确认 `--policy.dtype=bfloat16`；必要时扩 swap（与 π₀ 文档第八节同款） |
| `--policy.compile_model=true` 报错 | torch.compile 与 gradient_checkpointing / peft 兼容性 | 先关 compile_model，跑通后再开；或换 `--policy.compile_mode=default` |
| 训练极慢 / dataloader 打满 CPU | 视频帧解码瓶颈 | 确认系统 ffmpeg 已装；适当提高 `--num_workers` |
| ALOHA 训练报相机数不匹配 | pi05_base 期望 3 个相机（base + left_wrist + right_wrist），aloha 只有 1 个 | 加 `--policy.empty_cameras=2` 补 2 个空槽（见 5.2 节） |
| rollout 动作抖动 | 动作块边界未平滑 | 用 π₀ 默认 chunk 执行逻辑；必要时启用 temporal ensemble |
| **LIBERO 评估 env reset 报 `FileNotFoundError: .../libero/libero/assets/scenes/libero_tabletop_base_style.xml`**（✅ 实测 2026-08-28） | `hf-libero` 不捆绑仿真场景资源（587 个 XML/STL/纹理文件），`libero/__init__.py` 搜索优先级：**先 venv 本地 `libero/libero/assets/` → 再 HuggingFace**；评估脚本 `HF_HUB_OFFLINE=1` 直接挡住 HF 下载，venv 路径默认不存在 → 报错 | 4 步修复（见 6.3 节）：① `modelscope download --dataset lerobot/libero-assets --local_dir ~/.libero/assets`（587 文件，1 分 51 秒）② 在 venv 里建软链 `ln -sfn ~/.libero/assets <venv>/libero/libero/assets` ③ 更新 `~/.libero/config.yaml` ④ 训练/评估脚本 `ensure_libero_assets()` 已自动处理软链缺 |

> π₀ 文档第八节的所有排错项（5090 sm_120 cu128 约束、RAM OOM、lerobot-train ImportError、HF 超时、MuJoCo 渲染等）**对 π₀.₅ 同样适用**，详见 [17 号文档第八节](./17-pi0本地化部署py312与ALoHa仿真训练指南-v1.0.md)。
