## 0. 全景：一句话与三个数字

**一句话**：π₀.₅ 把 π₀ 的双流结构**原样继承**（PaliGemma VLM + 300M Action Expert + 联合自注意力 + Flow Matching），但在**输入表示**和**时间注入方式**上做了五处改动，目标是把 π₀ 的"实验室专才"升级成能在**从未见过的家庭**里做长程任务的"开放世界通才"。

**三个数字**（贯穿全文，先记住）：

| 数字 | 含义 | 源码印证 |
|------|------|---------|
| **3.3B ≈ 3.0B + 300M** | PaliGemma VLM 主干（SigLIP + Gemma 2B variant）+ Action Expert（Gemma 300M，从零初始化） | [configuration_pi05.py L31-32](file:///Users/damon/Documents/10_code/openSources/ws/101-pi-serial-models/repos/lerobot-main/src/lerobot/policies/pi05/configuration_pi05.py#L31)：`paligemma_variant="gemma_2b"`、`action_expert_variant="gemma_300m"`（**与 π₀ 完全相同**） |
| **97.6% 非目标平台** | 论文预训练数据里 97.6% 不来自目标机器人——靠异构 co-training 迁移实现开放世界泛化 | 论文报告"六、核心贡献总结"；lerobot 移植版**不含**预训练数据管线，只加载已训好的基座权重 |
| **H = 50 @ 50Hz** | 一次生成 50 步动作块，最高 50Hz 连续控制（`n_action_steps` 本地 LIBERO 常压到 10） | [configuration_pi05.py L36-37](file:///Users/damon/Documents/10_code/openSources/ws/101-pi-serial-models/repos/lerobot-main/src/lerobot/policies/pi05/configuration_pi05.py#L36)：`chunk_size=50`、`n_action_steps=50` |

**全景数据流**（后续每节展开其中一段；★ 标注与 π₀ 不同处）：

```
        ┌─────────────── 感知 ───────────────┐
图像(2~3路,224×224) ─ SigLIP ─┐                            ★可选 MEM 视频记忆(第7节)
任务文本 ─────────────────────┤
本体状态 qₜ ─ 离散成256bin ────┤→ [prefix: 图像token + "Task:..., State:...;Action:" 语言token]
        └──────────────────────┘        │        ★state 进 prompt 文本,不再走 state_proj(第6节)
                                          │  VLM 主干(PaliGemma)理解场景
                                          │  tokenizer_max_length=200 ★(π₀ 是 48)
噪声动作 Aₜ^τ ────── action_in_proj ─┐    │
时间步 τ ─ sinusoidal → time_mlp ────┤→ [suffix]  ★时间走 AdaRMS,不与动作 cat(第4.5节)
                                     │   ↑        │
                                     └── Action Expert(300M, use_adarms=True ★) ──┘
                                              │  联合自注意力(suffix 看 prefix 的 key/value)
                                              ▼
                                     action_out_proj → 速度场 v_θ
                                              │  Flow Matching: euler 积分 10 步(与 π₀ 同源)
                                              ▼
                                        50 步连续动作 → 执行
```

**核心范式**（呼应论文报告"一、研究动机"）：π₀ 证明了"通用 VLA 能做复杂任务"，π₀.₅ 要证明"它能在**从未见过的真实世界**里做"。论文的三大抓手——异构数据联合训练、层级推理、离散+连续混合动作——在 lerobot 移植版里的落地程度**并不一致**，本文会逐一标注（见 3.4、8.2）。

## 1. 研究动机：从"能做"到"在哪都能做"

> 呼应论文报告 **一、研究动机与问题定义**

### 1.1 核心问题：开放世界泛化

论文报告开篇把 π₀.₅ 要解决的问题钉在一句话上：

> **如何让 VLA 模型在从未见过的家庭环境中执行复杂的长视野操作任务？**（例如在全新厨房自主收拾餐具、在没见过的卧室整理衣物）

这个问题涉及**多层次泛化**：（1）简单物体操作可以靠堆数据泛化；（2）新环境中的技能组合需要适应性迁移；（3）场景语义理解需要从先验知识推理。π₀.₅ 的答案是**异构数据联合训练（co-training）**——用六类数据源在同一 curriculum 里训，让 97.6% 的非目标平台数据"喂"出泛化能力。

### 1.2 论文的三大创新（本文主线）

| 创新 | 含义 | 本文对应 | lerobot 移植版落地情况 |
|------|------|---------|:---:|
| **异构数据联合训练** | MM/ME/CE/HL/WD/VI 六类数据 co-training | 第 8 节 | ⚠️ 只加载训好的基座，**不含数据管线** |
| **层级推理** | 先预测高层子任务语言，再生成低层动作 | 第 3.4 节 | ❌ **未实现**（`sample_actions` 只做 flow matching） |
| **离散+连续混合动作** | FAST token 预训练 + Flow Matching 后训练 | 第 4、8.2 节 | ⚠️ **只有 Flow Matching 一路**，无 FAST/交叉熵 |

> **必须先建立的认知**：lerobot 的 `policies/pi05` 是 openpi 的**推理/微调移植版**，它实现的是论文里"**后训练阶段那个 Flow Matching action expert**"这一条路径。论文的预训练（FAST 自回归）、层级推理（high-level subtask 解码）在 lerobot 代码里**没有对应实现**——这不是 bug，而是移植范围的取舍。本文遇到这类"论文有、代码无"的地方会用 ❌/⚠️ 明确标出，避免你把论文能力当成代码能力。

### 1.3 为什么 π₀.₅ 不是"另起炉灶"

论文报告"前置回顾"说得很清楚：π₀.₅ **直接构建在 π₀ 之上**——继承双专家 Transformer 骨干与 Flow Matching，只在三处扩展。这个"继承"在代码里是**字面意义的**：`modeling_pi05.py` 顶部 import 的 `compute_layer_complete`、`get_gemma_config`、`PaliGemmaWithExpertModel` 结构与 `modeling_pi0.py` **几乎逐行同构**（[modeling_pi05.py L178/L261/L285](file:///Users/damon/Documents/10_code/openSources/ws/101-pi-serial-models/repos/lerobot-main/src/lerobot/policies/pi05/modeling_pi05.py#L178)），差异只集中在**投影头、时间注入、state 处理、MEM**这几处。所以本文的写法是：**π₀ 已讲透的部分（双流融合、Flow Matching 数学、掩码 cumsum 机制）只做"差异对照"，把篇幅留给 π₀.₅ 真正改动的地方**。

## 2. 架构总览：继承双流 + 五处改动

| **Action Expert** | 300M | Gemma 300M，从零初始化 | [modeling_pi05.py L341](file:///Users/damon/Documents/10_code/openSources/ws/101-pi-serial-models/repos/lerobot-main/src/lerobot/policies/pi05/modeling_pi05.py#L341) `self.gemma_expert` |

### 2.3 投影头：少了 state_proj，action_time_mlp 改名 time_mlp

这是改动 ①② 在 `__init__` 里的直接体现。π₀.₅ 的投影头（[modeling_pi05.py L548-557](file:///Users/damon/Documents/10_code/openSources/ws/101-pi-serial-models/repos/lerobot-main/src/lerobot/policies/pi05/modeling_pi05.py#L548)）：

```python
self.action_in_proj  = nn.Linear(config.max_action_dim, action_expert_config.width)   # L548 含噪动作(32)→Expert宽度(1024)
self.action_out_proj = nn.Linear(action_expert_config.width, config.max_action_dim)   # L549 Expert宽度→速度场(32)

self.time_mlp_in  = nn.Linear(action_expert_config.width, action_expert_config.width) # L551 ★只吃 time(1024),不再吃[action⊕time](2048)
self.time_mlp_out = nn.Linear(action_expert_config.width, action_expert_config.width) # L552
self.proprio_history_proj = (                                                          # L553 ★MEM 本体记忆投影(默认 None)
    nn.Linear(config.max_state_dim, paligemma_config.width)
    if config.use_proprioceptive_memory else None
)
```

| 投影头 | π₀（modeling_pi0 L430-435） | π₀.₅（modeling_pi05 L548-557） | 差异 |
|--------|------|------|------|

### 2.4 Token 预算：prefix 变长、suffix 只剩动作

沿用 26 号文档 2.4 的算法，但 π₀.₅ 两侧都变了。以本地 LIBERO（2 相机 + 1 空相机 = 3 路，`empty_cameras=1`）为例：

**Prefix（VLM 主干处理）**：
- 图像：SigLIP 每路 224×224 → **256 个视觉 token**，3 路 = **768**
- 语言：`Task: ..., State: <256bin 数字串>;\nAction: ` tokenize 到 `tokenizer_max_length=**200**` → **200 个语言 token**（π₀ 是 48）
- 小计：768 + 200 = **968**

**Suffix（Action Expert 处理）**：
- ~~状态~~：**π₀.₅ 没有 state token**（改动②，state 已进 prompt）
- 含噪动作：`chunk_size=50` → **50 个 token**
- 小计：**50**（π₀ 是 1 + 50 = 51）

**合计**：968 + 50 = **1018 个 token**（π₀ 三相机是 867）。

**三个数字的出处**：

**① 图像 256/路**——与 π₀ 同源：SigLIP-so400m-patch14-224，224÷14=16，16×16=256。代码 [`embed_prefix` L618-635](file:///Users/damon/Documents/10_code/openSources/ws/101-pi-serial-models/repos/lerobot-main/src/lerobot/policies/pi05/modeling_pi05.py#L618) 对每路相机循环，`num_img_embs = img_emb.shape[:2]`（[L630](file:///Users/damon/Documents/10_code/openSources/ws/101-pi-serial-models/repos/lerobot-main/src/lerobot/policies/pi05/modeling_pi05.py#L630)）。

**② 语言 200 为什么要这么长**——π₀.₅ 的 prompt 不再只是"一句指令"，而是**指令 + 离散化 state 数字串 + 控制模式标记**（改动②③）。[processor_pi05.py L84](file:///Users/damon/Documents/10_code/openSources/ws/101-pi-serial-models/repos/lerobot-main/src/lerobot/policies/pi05/processor_pi05.py#L84) 拼出的字符串形如：

```
Task: put the black bowl on the plate, State: 128 127 130 128 129 131 ...;\nAction: 
```

一个 32 维 state 每维离散成 0~255 的整数、空格分隔，光 state 串就可能占几十个 token；再叠加论文 3.4 提到的 `<control mode> joint/end effector <control mode>` 特殊 token 和 BDDL 式长任务描述——**48 根本装不下，所以涨到 200**。

**③ suffix 只剩 50**——`embed_suffix`（[modeling_pi05.py L667-704](file:///Users/damon/Documents/10_code/openSources/ws/101-pi-serial-models/repos/lerobot-main/src/lerobot/policies/pi05/modeling_pi05.py#L667)）里 `att_masks += [1] + ([0] * (chunk_size - 1))`（[L700](file:///Users/damon/Documents/10_code/openSources/ws/101-pi-serial-models/repos/lerobot-main/src/lerobot/policies/pi05/modeling_pi05.py#L700)），只有 50 个动作 token，**没有 π₀ 那个 state token**。这直接导致第 5 节的注意力块从"三块"变"两块"。

### 2.5 融合 Transformer：`use_adarms=[False, True]` 的含义

26 号文档 2.5 讲过，π₀ 的融合 Transformer 是 `PaliGemmaWithExpertModel` 逐层 zip 出来的复合体，且 **π₀ 的 `use_adarms=[False, False]`**（两条流都不启用 AdaRMS，时间靠 cat+MLP 注入）。π₀.₅ 在这里做了**关键的一处改动**（[modeling_pi05.py L538-546](file:///Users/damon/Documents/10_code/openSources/ws/101-pi-serial-models/repos/lerobot-main/src/lerobot/policies/pi05/modeling_pi05.py#L538)）：

```python
self.paligemma_with_expert = PaliGemmaWithExpertModel(
    paligemma_config,
    action_expert_config,
    use_adarms=[False, True],   # L541 ★VLM 侧不用 AdaRMS，Expert 侧启用 AdaRMS
    precision=config.dtype,
    image_size=config.image_resolution[0],
    freeze_vision_encoder=config.freeze_vision_encoder,
    train_expert_only=config.train_expert_only,
)
```

`use_adarms=[False, True]` 的两位分别对应 `[VLM, Expert]`：

- **VLM 侧 = False**：prefix（图像+语言）走标准 GemmaRMSNorm，保护 PaliGemma 预训练分布不被污染（与 π₀ 一致）。
- **Expert 侧 = True**：suffix（含噪动作）的每一层 RMSNorm 被替换成 **`PiGemmaRMSNorm`（AdaRMS）**，由时间条件向量 `adarms_cond` 调制 scale/shift/gate。

这个 `True` 就是改动①的落地点，也是论文报告 3.3 那句话的源码形态：

> 与 π0 不同，π0.5 **不再将流匹配时间步 τ 与带噪动作融合后送入 Transformer**，而是用独立 MLP 投影 τ，再通过 **adaptive RMSNorm** 将时间步信息注入 action expert 的每一层。

AdaRMS 的具体数学与代码在第 4.5 节展开。这里先记住结论：**π₀ 时间是"拼进动作 token"，π₀.₅ 时间是"调制每一层归一化"**——这是 DiT 风格的自适应条件化，比 cat+MLP 更强，因为它在**每一层**都重新注入时间信息，而不只在输入端注入一次。

### 2.6 维度：2048 / 1024 / 256 与 π₀ 同源

`get_gemma_config`（[modeling_pi05.py L261-282](file:///Users/damon/Documents/10_code/openSources/ws/101-pi-serial-models/repos/lerobot-main/src/lerobot/policies/pi05/modeling_pi05.py#L261)）与 π₀ **逐字段相同**：

```python
gemma_2b  : width=2048, depth=18, mlp_dim=16384, num_heads=8, num_kv_heads=1, head_dim=256  # L272-280 VLM
```

所以 26 号文档 2.6 的全部结论**原样适用**于 π₀.₅：prefix 宽 2048、suffix 宽 1024、head_dim=256、**注意力头数是 8（不是 18，18 是 depth 层数）**、GQA（8Q 共享 1KV）、合并注意力维 = `8×256=2048`。[L224](file:///Users/damon/Documents/10_code/openSources/ws/101-pi-serial-models/repos/lerobot-main/src/lerobot/policies/pi05/modeling_pi05.py#L224) `att_output.reshape(batch_size, -1, 1 * 8 * head_dim)` 里的 `1*8*256=2048` 同样坐实头数是 8。

> **一句话**：π₀.₅ 的"公共注意力空间"与 π₀ 完全一致——异构双流能在同一次注意力里交互，靠的是 `head_dim=256`、`num_heads=8`、`num_kv_heads=1` 三者对齐，而非某个大的公共维度。**"18 头 / 4608" 的误传在 π₀.₅ 上同样不成立。**

### 3.3 select_action 的 action queue（chunk 如何落地执行）

与 π₀ 完全同款（[modeling_pi05.py L1298-1315](file:///Users/damon/Documents/10_code/openSources/ws/101-pi-serial-models/repos/lerobot-main/src/lerobot/policies/pi05/modeling_pi05.py#L1298)）：

```python
def select_action(self, batch):
    self.eval()
    if self.config.use_visual_memory or self.config.use_proprioceptive_memory:
        batch = self._stack_inference_memory(batch)              # L1307 MEM 开启才走(默认关)
    if len(self._action_queue) == 0:                            # 队列空了才重新预测
        actions = self.predict_action_chunk(batch)[:, : self.config.n_action_steps]  # L1311 取前 n_action_steps 步
        self._action_queue.extend(actions.transpose(0, 1))      # L1313 入队
    return self._action_queue.popleft()                         # L1315 每帧弹出 1 步
```

### 3.4 论文的层级推理 vs 代码现实（★重要澄清）

论文报告"二、方法概述·层级推理架构"给出 π₀.₅ 推理的**两阶段层级结构**：

1. **高层推理** \(\pi_\theta(\hat\ell\mid o_t,\ell)\)：根据当前观测和高层命令（"打扫卧室"）**自回归预测下一个子任务**（"捡起枕头"）；
2. **低层推理** \(\pi_\theta(a_{t:t+H}\mid o_t,\hat\ell)\)：以子任务为条件，用 action expert 生成连续动作块。

数学上是联合策略的因式分解：

$$\pi_\theta(a_{t:t+H}, \hat\ell \mid o_t, \ell) = \underbrace{\pi_\theta(\hat\ell\mid o_t,\ell)}_{\text{高层:预测子任务语言}} \cdot \underbrace{\pi_\theta(a_{t:t+H}\mid o_t,\hat\ell)}_{\text{低层:生成连续动作}}$$

**但 lerobot 移植版只实现了低层那一项**。证据：

| 论文层级推理要素 | lerobot `policies/pi05` 是否实现 | 源码证据 |
|---|:---:|---|
| 低层：Flow Matching 生成动作块 | ✅ 实现 | `sample_actions` [L768](file:///Users/damon/Documents/10_code/openSources/ws/101-pi-serial-models/repos/lerobot-main/src/lerobot/policies/pi05/modeling_pi05.py#L768) 只做 euler 积分 |
| 高层：自回归解码子任务语言 \(\hat\ell\) | ❌ **未实现** | `sample_actions` 全程无 `generate()` / 无 token 采样；`gemma_expert.model.embed_tokens = None`（[L342](file:///Users/damon/Documents/10_code/openSources/ws/101-pi-serial-models/repos/lerobot-main/src/lerobot/policies/pi05/modeling_pi05.py#L342)），Expert 连词嵌入都被摘掉 |
| 高层：先预测 bounding box 再预测子任务标签 | ❌ 未实现 | 无检测头、无 box 相关代码 |

> **怎么理解这个差异**：lerobot 的 `pi05` 是 openpi 的**动作生成内核移植**——它加载的 `pi05_base` / `pi05_libero_base` 权重是 Physical Intelligence 用完整层级推理训好的，但 lerobot 侧**只跑低层 Flow Matching 这一路**。在 LIBERO 这类"单步指令直接对应一段操作"的 benchmark 上，高层子任务预测收益有限（任务描述本身就是子任务），所以只用低层就能打到 98.4%（第 8.3 节）。**要做论文那种"打扫卧室→捡枕头→放枕头"的长程分解，需要 openpi 原版或自己补高层解码链，lerobot 现成代码给不了。**

### 3.5 论文层级推理的运行逻辑深拆（子任务如何拆、如何交接）

> 本节承接 §3.4，把论文层级推理的**运行机制**讲透，澄清三个高频误解：子任务是不是固定拆成几个、循环怎么跑、下一个子任务依赖什么。**以下全部是 π₀.₅ 论文机制，lerobot 本地代码不实现（见 §3.4）。**

#### 3.5.1 子任务不是"预先拆成固定 3/4 个"，而是动态逐个预测

论文明确写的是"根据当前观测和高层命令**预测下一个子任务**"（报告 md L84），关键词是"**下一个**"——模型**一次只吐一个**子任务标签 \(\hat\ell\)，边看边决定下一步，**没有开局一次性拆成一份固定清单**这回事。因此子任务个数是**运行时涌现**的，由观测反馈决定，不硬编码 3 或 4。

> ⚠️ **"3 还是 4"这个印象从哪来**：很可能来自论文评测的**评分标准表（rubric）**——"餐具入水槽 8 分 / 物品入抽屉 4 分 / 衣物入篮 3 分 / 整理床铺 5 分"（报告 md L227-234）。但那是人工设计、用来判成功与算分的**评分项**，每个任务还不一样（3/4/5/8 都有），**不是模型实际拆出的子任务数**。两者别混。
>
> **怎么识别/确认实际拆了几个**：只能靠**运行时日志**——把每个 chunk 高层解码出的文本 \(\hat\ell\) 打出来，数它连续吐了哪几个不同标签。标签的取值范围来自 **HL 训练数据**：那里每条样本都人工标注了子任务标签 + 边界框（报告 md L76、L91），模型学的就是这个条件分布；推理时还要求**先预测 bounding box 再预测子任务标签**，把子任务"落地"到具体空间位置。

#### 3.5.2 运行循环：先高层出子任务，再低层出动作，每 chunk 重跑高层

```
① 给高层命令 ℓ("打扫卧室") + 初始观测 o₀
        │  自回归解码(先 bbox 再标签) —— 此步不出动作
        ▼
   子任务 ℓ̂₁("捡起枕头")
        │  以 ℓ̂₁ 为语言条件
        ▼
② action expert 做 10 步 Flow Matching → 动作块 chunk₁ → 执行
        │  拿到新观测 o₁
        ▼
③ 【关键】每个 chunk 前高层都重跑 πθ(ℓ̂|o_t,ℓ)：
     · 画面显示 ℓ̂₁ 还没做完 → 继续吐 ℓ̂₁（看起来像"轮询执行同一子任务"）
     · 画面显示 ℓ̂₁ 已完成   → 自动翻到 ℓ̂₂ → 交接发生
        │
        └──────────────回到 ② 用 ℓ̂₂ 生成下一动作块
```

**这里要修正一个常见误解**：模型**没有一个显式的"子任务是否执行完毕"的检测器/门控**。不是"执行完毕后再去预测下一个子任务"，而是**每个动作块生成前高层都重新预测一次**。"执行完再交接"是**涌现效果**——只要画面还显示 ℓ̂₁ 未完成，高层就持续重吐 ℓ̂₁；一旦画面变了，同一次预测自然翻到 ℓ̂₂。交接发生在 **chunk 边界**，靠视觉反馈驱动，不是代码里的 if 判断。

#### 3.5.3 下一个子任务依赖什么？—— 依赖 ℓ + o_t，不显式依赖上一个子任务

看因子分解（报告 md L86）：

$$\pi_\theta(\hat\ell \mid o_t, \ell)$$

条件项只有两个：**当前观测 `o_t`** 和**高层命令 `ℓ`**。**公式里没有 \(\hat\ell_{prev}\)（上一个子任务）这一项。** 上一个子任务的影响是**隐式**地通过"观测已经变了"体现的——例如"盘子已在水槽里"这个画面本身就编码了上一步成果，模型据此判断下一步。

**一个有力佐证**（报告 md L219 的局限）：π₀.₅ 会出现"**重复开关抽屉的循环行为**"。如果它显式记得"我刚做过 open_drawer"，就不该反复做同一动作——正因为它是**纯看当前画面重新决定、不显式携带上一个子任务的记忆**，才可能卡进循环。这反证了 \(\hat\ell_{prev}\) 不是显式输入。

> **另一个易混点**：报告说"标准自回归解码生成文本 token"（L149）——那个自回归是**在单个子任务标签内部逐 token 生成**（"put plate in sink" 一个词一个词吐），**不是**"把上一个子任务喂回去预测下一个"。

#### 3.5.4 一句话总结

**循环方向**：先高层出子任务、再低层出动作、观测驱动前进；**但高层是每个 chunk 都重跑**（无显式完成检测器）；**下一个子任务只依赖「高层命令 ℓ + 当前观测 o_t」，不显式依赖上一个子任务**（其影响通过画面变化隐式传递，"重复开关抽屉"的循环失败正是佐证）；**子任务个数动态涌现、非固定 3/4**（rubric 评分项 ≠ 子任务数）。**再次强调：以上均为论文机制，lerobot `pi05` 本地代码不实现。**

## 4. Flow Matching：原理与代码（含 AdaRMS 时间注入）

> 呼应论文报告 **前置回顾·条件流匹配** + **3.3 Action Expert 实现细节** + **3.1 离散+连续动作表示**

### 4.1 原理：与 π₀ 同源的直线速度场

Flow Matching 的三个核心公式**与 π₀ 完全一致**（26 号文档 4.1 已推导），此处只列结论：

$$A_t^\tau = \tau\cdot\epsilon + (1-\tau)\cdot A_t \qquad(\tau=1\text{ 纯噪声},\ \tau=0\text{ 纯动作})$$
$$u = \epsilon - A_t \qquad(\text{目标速度场,直线方向})$$
$$L^\tau(\theta) = \mathbb{E}\big\| v_\theta(A_t^\tau, o_t) - u \big\|^2 \qquad(\text{条件流匹配损失})$$

> **注意符号约定**：论文报告"前置回顾"用的是 \(x_t=(1-t)x_0+t x_1\)（t=0 噪声、t=1 动作），而 **lerobot 源码用 \(\tau=1\) 噪声、\(\tau=0\) 动作**（`x_t = time*noise + (1-time)*actions`）。两者是同一条直线、方向相反的参数化，代码以源码约定为准（下文一律用源码约定）。

论文 3.1 还给出**离散+连续混合损失**：

$$L = \underbrace{\mathcal{H}(x_{1:M}, f^\ell_\theta(o_t,\ell))}_{\text{FAST 交叉熵(预训练)}} + \alpha\cdot\underbrace{\mathbb{E}\|\omega - a_{t:t+H} - f^a_\theta(\cdot)\|^2}_{\text{Flow Matching(后训练)}},\quad \alpha=10.0$$

**lerobot 只实现第二项**（Flow Matching MSE，α 项），第一项 FAST 交叉熵在移植版里**不存在**（见 8.2）。

### 4.5 ★时间注入：AdaRMS 取代 cat+MLP（π₀.₅ 核心改动）

这是 π₀.₅ 相对 π₀ **最实质的架构改动**，也是论文报告 3.3 的重点。分三步看。

**第一步：`embed_suffix` 里时间怎么变成 `adarms_cond`**（[modeling_pi05.py L667-704](file:///Users/damon/Documents/10_code/openSources/ws/101-pi-serial-models/repos/lerobot-main/src/lerobot/policies/pi05/modeling_pi05.py#L667)）：

```python
def embed_suffix(self, noisy_actions, timestep):        # ★签名无 state(对比 π₀ embed_suffix(state, x_t, time))
    # ① 标量 t → 1024 维正弦编码(与 π₀ 同款 create_sinusoidal_pos_embedding)
    time_emb = create_sinusoidal_pos_embedding(          # L672
        timestep, self.action_in_proj.out_features,      #   dimension=1024
        min_period=self.config.min_period,               #   4e-3
        max_period=self.config.max_period,               #   4.0
        device=timestep.device)
    # ② 动作单独投影(不再与时间 cat!)
    action_emb = self.action_in_proj(noisy_actions)      # L685 (B,50,32)→(B,50,1024)
    # ③ 时间单独过两层 MLP(swish/silu),得到 AdaRMS 条件向量
    def time_mlp_func(time_emb):                         # L687-691
        x = self.time_mlp_in(time_emb)                   #   Linear(1024→1024)
        x = F.silu(x)                                    #   swish
        x = self.time_mlp_out(x)                         #   Linear(1024→1024)
        return F.silu(x)                                 #   swish
    time_emb = self._apply_checkpoint(time_mlp_func, time_emb)  # L693
    adarms_cond = time_emb                               # L694 ★这就是注入每层的条件向量(π₀ 这里是 None!)
    ...
    att_masks += [1] + ([0] * (self.config.chunk_size - 1))     # L700 ★只有 50 个动作 token(无 state)
    return action_emb, pad_masks, att_masks, adarms_cond # L704 ★返回非 None 的 adarms_cond
```

对照 π₀ 的 `embed_suffix`（26 号文档 4.5）：π₀ 是 `action_time_emb = torch.cat([action_emb, time_emb], dim=2)` → `action_time_mlp_in(2048→1024)`，且末尾 `adarms_cond = None`。π₀.₅ **把 cat 去掉**，动作和时间**各走各的**：动作 → `action_in_proj` → suffix token；时间 → `time_mlp` → `adarms_cond`。论文报告 3.3 的时间 MLP 形式 \( \text{swish}(W_2\cdot\text{swish}(W_1\cdot\varphi(\tau))) \) 精确对应 L687-691（\(\varphi\)=正弦编码，两层 Linear + silu）。

**第二步：AdaRMS 怎么用 `adarms_cond` 调制每一层**（[pi_gemma.py L85-141](file:///Users/damon/Documents/10_code/openSources/ws/101-pi-serial-models/repos/lerobot-main/src/lerobot/policies/pi_gemma.py#L85)）。Expert 侧每层的 `input_layernorm` / `post_attention_layernorm` 都是 `PiGemmaRMSNorm`：

```python
class PiGemmaRMSNorm(nn.Module):        # pi_gemma.py L85 "Adaptive RMSNorm for PI Gemma (AdaRMS)"
    def __init__(self, dim, eps=1e-6, cond_dim=None):
        if cond_dim is not None:
            self.dense = nn.Linear(cond_dim, dim * 3, bias=True)   # L103 ★一个 Linear 产出 scale/shift/gate 三份
            nn.init.zeros_(self.dense.weight)                      # L104 零初始化(训练初期等价标准 RMSNorm)
        else:
            self.weight = nn.Parameter(torch.zeros(dim))           # L106 无条件时退回标准 RMSNorm
    def forward(self, x, cond=None):
        normed = self._norm(x)                                     # L122 先做 RMS 归一化
        if cond is None or self.dense is None:                     # L123 VLM 侧走这里(cond=None)
            return normed * (1.0 + self.weight.float()), None      # L124 标准 GemmaRMSNorm
        modulation = self.dense(cond)                              # L134 ★cond=adarms_cond(时间)→调制量
        scale, shift, gate = modulation.chunk(3, dim=-1)           # L139 拆成三份
        normed = normed * (1 + scale.float()) + shift.float()      # L140 ★scale/shift 调制归一化输出
        return normed.to(dtype), gate.to(dtype)                    # L141 gate 供 _gated_residual 用
```

**第三步：gate 怎么进残差**（[pi_gemma.py L54-60 `_gated_residual`](file:///Users/damon/Documents/10_code/openSources/ws/101-pi-serial-models/repos/lerobot-main/src/lerobot/policies/pi_gemma.py#L54) + [compute_layer_complete L185/L235/L243](file:///Users/damon/Documents/10_code/openSources/ws/101-pi-serial-models/repos/lerobot-main/src/lerobot/policies/pi05/modeling_pi05.py#L185)）：AdaRMS 返回的 `gate` 被用在两个残差上——`x + y*gate`（gate 为 None 时退回 `x + y`）。于是**时间信息通过 scale/shift/gate 三个通道，在 Expert 的每一层、每个残差处反复注入**。

**为什么 AdaRMS 比 cat+MLP 强**：

| 维度 | π₀：cat + MLP | π₀.₅：AdaRMS |
|---|---|---|
| 注入位置 | **只在输入端**注入一次（拼进动作 token） | **每一层**的 RMSNorm 都注入 |
| 注入方式 | 特征维拼接 → MLP | scale/shift/gate 三通道调制归一化 |
| 与动作的关系 | 时间和动作**耦合**在同一个 token | 时间和动作**解耦**（动作是 token，时间是条件） |
| 参数开销 | `action_time_mlp_in` 输入 2048 | 每层多一个 `Linear(1024→3072)`，零初始化 |
| 类比 | — | DiT 的 AdaLN-Zero（`nn.init.zeros_` 正是 Zero 初始化） |

> **咬合论文**：论文报告 3.3"用独立 MLP 投影 τ，再通过 adaptive RMSNorm 将时间步信息注入 action expert 的每一层"——`独立 MLP`=L687-691 的 `time_mlp_func`，`adaptive RMSNorm`=L85 的 `PiGemmaRMSNorm`，`每一层`=Expert 18 层每层的 input/post_attention 两个 norm。`use_adarms=[False, True]`（L541）保证**只有 Expert 侧**被调制，VLM 侧仍是标准 RMSNorm。doc 24 也提到"AdaRMS 这个名字在源码里是真实类名 `PiGemmaRMSNorm` + docstring"，本文 L85-88 的 docstring 就是出处。

> **推理 vs 训练：注入机制相同**。推理侧 10 步的 t 由 `euler_integrate` 均匀步进（1.0→0.1，`dt=-0.1`），训练侧 t 由 `sample_time_beta` 随机采样；但两者都经**同一条 `embed_suffix` → `adarms_cond` → AdaRMS** 链注入，与 π₀ 的"注入机制相同、t 来源不同"结论一致。

## 5. 注意力掩码：从 π₀ 的三块变成两块

> 呼应论文报告 **3.2 注意力掩码设计**（Figure 18）

### 5.1 机制不变：拼成一个序列，用掩码控制可见性

π₀.₅ 与 π₀ 一样，**不用 cross-attention**，而是把 prefix（图像+语言，含离散 state）和 suffix（含噪动作）拼成一个长序列，一起过共享自注意力层，靠 `att_masks` + `make_att_2d_masks`（[vla_utils.py L60-90](file:///Users/damon/Documents/10_code/openSources/ws/101-pi-serial-models/repos/lerobot-main/src/lerobot/policies/common/vla_utils.py#L60)，与 π₀ 共用同一函数）规定"谁能看谁"。信息流仍是**单向 VLM → Action Expert**。

`make_att_2d_masks` 的核心两行（π₀/π₀.₅ 共用，[vla_utils.py L86-87](file:///Users/damon/Documents/10_code/openSources/ws/101-pi-serial-models/repos/lerobot-main/src/lerobot/policies/common/vla_utils.py#L86)）：

```python
cumsum = torch.cumsum(att_masks, dim=1)                 # L86 att_masks 累积求和 → 每个 token 的"块号"
att_2d_masks = cumsum[:, None, :] <= cumsum[:, :, None] # L87 token i 能看 j ⟺ cumsum[j] ≤ cumsum[i]
```

`att_masks` 语义：**`1`** = 开启新块（前面看不到它，因果边界）；**`0`** = 与前一同块（块内双向）。

### 5.2 att_masks 怎么填：prefix 全 0，suffix 只剩 [1]+[0]×49

**`embed_prefix`（图像+语言）——全填 0**（[modeling_pi05.py L635/L656](file:///Users/damon/Documents/10_code/openSources/ws/101-pi-serial-models/repos/lerobot-main/src/lerobot/policies/pi05/modeling_pi05.py#L635)）：

```python
att_masks += [0] * num_img_embs    # L635 每个图像 token = 0
att_masks += [0] * num_lang_embs   # L656 每个语言 token = 0(含拼进去的离散 state 串)
```

**`embed_suffix`（只有动作）——首填 1、其余填 0**（[modeling_pi05.py L700](file:///Users/damon/Documents/10_code/openSources/ws/101-pi-serial-models/repos/lerobot-main/src/lerobot/policies/pi05/modeling_pi05.py#L700)）：

```python
# L699 注释:image, language and state inputs do not attend to action tokens
att_masks += [1] + ([0] * (self.config.chunk_size - 1))   # L700 首个动作=1,其余49个=0
```

**关键对比**：π₀ 的 `embed_suffix` 里先有 `att_masks += [1]`（state token，modeling_pi0 L548），再有 `[1]+[0]*49`（动作）——所以 π₀ 的 suffix 是 `[1](state) + [1,0×49](action)`。π₀.₅ **删掉了 state 那一个 `[1]`**（改动②），suffix 只剩 `[1]+[0]×49`。

以 LIBERO 3 相机（768 图像 + 200 语言）为例，完整 `att_masks`：

```
π₀.₅:  [0]×768(图像) + [0]×200(语言,含离散state) + [1,0×49](动作)
        = [0]×968(prefix)                        + [1] + [0]×49(suffix)
π₀ 对照: [0]×304(图+语) + [1](state) + [1,0×49](动作)   ← π₀ 多一个 state 的 [1]
```

### 5.3 cumsum 推导：π₀.₅ 只有两个 Block

对 5.2 的 `att_masks` 做 `cumsum`：

| 区段 | token 数 | att_mask | **cumsum（块号）** | 对应 Block |
|------|---------|----------|:---:|------|
| 图像 + 语言（含离散 state） | 968 | 全 0 | **0** | Block 1 |
| 首个动作 | 1 | 1 | **1** | Block 2 |
| 其余动作 | 49 | 全 0 | **1** | Block 2 |

代入规则 `i 看 j ⟺ cumsum[j] ≤ cumsum[i]`：

```
              j →   Block1(图+语+离散state)   Block2(action)
   i ↓               cumsum=0                  cumsum=1
 ┌────────────────────────────────────────────────────────┐
Block1(图+语+state) │      ✓ 双向               ✗          │  只看自己
Block2(action)      │      ✓                   ✓ 双向      │  看全部
 └────────────────────────────────────────────────────────┘
```

**与 π₀ 的三块对照**（26 号文档 5.4）：

| | π₀（三块） | π₀.₅（两块） |
|---|---|---|
| Block 1 | 图像 + 语言（cumsum=0） | 图像 + 语言 **+ 离散 state**（cumsum=0） |
| Block 2 | **本体状态 qₜ**（cumsum=1） | ~~不存在~~ |
| Block 3 / Block 2 | 含噪动作（cumsum=2） | 含噪动作（cumsum=**1**） |

> **本质差异**：π₀ 把 state 当作**独立的 suffix token**（Block 2，走 `state_proj`，可被 KV cache）；π₀.₅ 把 state **离散化后塞进 prompt 文本**，成了 prefix 的一部分（Block 1）。所以 π₀.₅ 的注意力块少了一块，动作 token 的 cumsum 从 2 降到 1。**state 从"后缀里的连续 token"变成"前缀里的文本 token"**——这是改动②在注意力层面的直接后果。

### 5.4 论文 Figure 18 的"两种动作表示互不干扰" vs 代码现实

论文报告 3.2 描述 Figure 18 的完整掩码有**四类 token**：前缀块（图像/语言/本体状态）、**FAST 动作 token**、**Action Expert 嵌入**，并强调：

> - FAST 动作 token 关注前缀，并对之前的动作 token 自回归（因果）可见；
> - Action Expert 嵌入关注前缀和彼此，但**不关注 FAST 动作 token**——避免两种动作表示之间的信息泄漏。

**lerobot 移植版只有"前缀块 + Action Expert 嵌入"两类**，没有 FAST 动作 token（因为没实现离散动作路径，见 8.2）。所以论文 Figure 18 里"FAST ↔ Expert 互不干扰"那条掩码规则，在 lerobot 代码里**无从体现**——`make_att_2d_masks` 生成的就是 5.3 的两块掩码。论文报告 3.2 前两条（前缀 full mask 内部双向、信息 VLM→Expert 单向）在代码里成立；后两条（FAST 相关）属于**未移植部分**。

### 5.5 这套掩码为什么这么设计（继承 π₀ 的四个理由，state 部分微调）

1. **Block1 只看自己 → 保护 VLM 预训练分布**：图像/语言（含离散 state 串）之间注意力与 PaliGemma 预训练一致，不被动作数据污染。
2. **state 进 prefix → 与 π₀ 的"可缓存"殊途同归**：π₀ 靠"state 独立成块且看不到 action"实现可缓存；π₀.₅ 把 state 并入 prefix，**天然随 prefix 一起被 KV cache**（prefix 只 forward 一次），同样不随去噪步变化。
3. **Block2（动作）看全部 → VLM→Expert 信息通道**：动作 token 能查询图像语义 + 语言指令 + 离散 state，无需独立 cross-attention。
4. **prefix 看不到 action → 因果律 + 梯度导向**：与 π₀ 一致，动作预测不反向干扰视觉理解，梯度天然引向 Expert 侧（呼应 8.4 的 LoRA 只打 Expert）。

### 5.6 KV 缓存为什么成立（与 π₀ 同）

因为 **Block1（图像+语言+离散 state）看不到 Block2（动作）**，Block1 的 key/value 与去噪步无关，所以 `sample_actions` 里 prefix 只 forward 一次存进 `past_key_values`（[L806](file:///Users/damon/Documents/10_code/openSources/ws/101-pi-serial-models/repos/lerobot-main/src/lerobot/policies/pi05/modeling_pi05.py#L806)），10 步去噪里 `denoise_step` 反复 `clone_past_key_values` 复用（[L874](file:///Users/damon/Documents/10_code/openSources/ws/101-pi-serial-models/repos/lerobot-main/src/lerobot/policies/pi05/modeling_pi05.py#L874)），每步只重算动作。**掩码设计与推理提速在这里闭环**，逻辑与 π₀ 完全一致。

- **每 N 层插一次时空注意力**：`temporal_layers = [i for i in range(len(layers)) if (i+1) % temporal_attention_every == 0]`（[memory L216](file:///Users/damon/Documents/10_code/openSources/ws/101-pi-serial-models/repos/lerobot-main/src/lerobot/policies/pi05/memory.py#L216)），这些层用 `space_time_attention`（[L124](file:///Users/damon/Documents/10_code/openSources/ws/101-pi-serial-models/repos/lerobot-main/src/lerobot/policies/pi05/memory.py#L124)）替代普通空间注意力。
- **复用 SigLIP 预训练 q/k/v，不加新参数**：`space_time_attention` 把注意力拆成"时间维（每个 patch 跨帧）+ 空间维（每帧跨 patch）"两次 SDPA，组合而非堆叠（[memory L156-174](file:///Users/damon/Documents/10_code/openSources/ws/101-pi-serial-models/repos/lerobot-main/src/lerobot/policies/pi05/memory.py#L156)）——`T==1` 时退化为标准 SigLIP 空间注意力。
- **过去帧在最后一个时间层后被丢弃**：`hidden_states = hidden_states[:, -1:]`（[memory L248](file:///Users/damon/Documents/10_code/openSources/ws/101-pi-serial-models/repos/lerobot-main/src/lerobot/policies/pi05/memory.py#L248)），所以**下游 VLM prefix 看到的仍是单帧的 256 个 token**——历史帧只在 SigLIP 内部融合了时空信息，不额外增加 prefix token 数。

### 7.3 本体记忆：`proprio_history_proj`

开 `use_proprioceptive_memory` 后，历史 state 走**连续投影**而非离散化进 prompt（与 6.1 二选一）：

- `proprio_history_proj = nn.Linear(max_state_dim, paligemma_config.width)`（[modeling L553-557](file:///Users/damon/Documents/10_code/openSources/ws/101-pi-serial-models/repos/lerobot-main/src/lerobot/policies/pi05/modeling_pi05.py#L553)）把每帧 state 投影到 VLM 宽度，作为 prefix token 插入（`embed_prefix` [L637-644](file:///Users/damon/Documents/10_code/openSources/ws/101-pi-serial-models/repos/lerobot-main/src/lerobot/policies/pi05/modeling_pi05.py#L637)，`att_masks += [0]*state_embs.shape[1]`）。
- 推理时 `_stack_inference_memory`（[modeling L1261](file:///Users/damon/Documents/10_code/openSources/ws/101-pi-serial-models/repos/lerobot-main/src/lerobot/policies/pi05/modeling_pi05.py#L1261)）维护一个环形队列，`sample_observation_history`（[memory L68](file:///Users/damon/Documents/10_code/openSources/ws/101-pi-serial-models/repos/lerobot-main/src/lerobot/policies/pi05/memory.py#L68)）按 age 采样历史帧。
- 这个投影**不存在于 `lerobot/pi05_base`**，所以 LoRA 微调时要 `modules_to_save=["model.proprio_history_proj"]` 全量训练保存（[modeling L1411-1415](file:///Users/damon/Documents/10_code/openSources/ws/101-pi-serial-models/repos/lerobot-main/src/lerobot/policies/pi05/modeling_pi05.py#L1411)），否则它会停在随机初始化。

### 7.4 MEM vs action queue：别混为一谈

doc 24 特别强调过这个易混点，本文用代码钉死：

| 机制 | 作用 | 代码 | 默认 |
|---|---|---|:---:|
| **MEM 记忆** | 给模型喂**历史观测**（过去 6 帧图像/state） | `memory.py` + `use_*_memory` 开关 | **关** |
| **action queue** | 一次预测 50 步、**执行 n_action_steps 步**再重预测 | `select_action` deque（[L1310-1315](file:///Users/damon/Documents/10_code/openSources/ws/101-pi-serial-models/repos/lerobot-main/src/lerobot/policies/pi05/modeling_pi05.py#L1310)） | 开 |

把 `n_action_steps` 从 50 压到 10 是 **action queue** 的行为（每次只执行 10 步），**不是 MEM**。两者一个管"输入历史"、一个管"输出执行",完全正交。

## 8. 预训练与后训练：异构 co-training + 本地 LIBERO

> 呼应论文报告 **二·核心创新：异构数据联合训练** + **四、训练策略** + **五、实验与评测**

### 8.1 论文的六类异构数据（数据地图）

论文报告用"数据地图"讲清 π₀.₅ 的 co-training 配方——**97.6% 训练数据不来自目标机器人平台**：

| 代号 | 数据源 | 规模/说明 | 叙事功能 |
|:---:|------|------|------|
| **MM** | 移动操作机器人 | ~400 小时、~100 个家庭 | "最直接相关但最少" |
| **ME** | 多环境非移动机器人 | 单/双臂固定机器人、多家庭 | "更多环境覆盖" |
| **CE** | 跨具身实验室数据 | 多种机器人 + OXE 开源 | "更多任务覆盖"（**只用于预训练**） |
| **HL** | 高层子任务预测 | 场景理解 + 子任务标签 + 边界框 | "语义推理能力" |
| **WD** | 多模态网络数据 | 图文描述/VQA/物体定位 | "物体知识泛化" |
| **VI** | 口头语言指令 | 专家语言"演示"，约占高层样本 11% | "人类监督模态"（**后训练才加**） |

消融实验（论文 Figure 10-13）的关键结论：移除 ME/CE 显著降性能；移除 WD 对 **OOD 物体语言跟随**影响最大；完整 π₀.₅ 的高层推理**甚至超过人类专家 oracle**；GPT-4 零样本高层策略垫底（证明高层策略必须用机器人数据适配 VLM）。

### 8.2 论文两阶段训练 vs lerobot 移植版（★重要澄清）

论文报告"四、训练策略"给出两阶段：

| 阶段 | 步数 | 动作表示 | 关键数据 |
|------|------|----------|----------|
| **预训练** | 280k | 离散（**FAST**），α=0 | MM+ME+CE+HL+WD |
| **后训练** | 80k | 离散 + 连续（**Flow Matching**），α=10.0 | MM+ME+HL+WD+VI |

**lerobot 移植版只覆盖"后训练的 Flow Matching 那一路"**：

| 论文训练要素 | lerobot `policies/pi05` | 证据 |
|---|:---:|---|
| 预训练：FAST 离散 token 自回归 | ❌ 未实现 | 无 FAST tokenizer、无交叉熵损失项 |
| 后训练：Flow Matching 连续动作 | ✅ 实现 | `forward` 只有 `F.mse_loss(u_t,v_t)`（[L766](file:///Users/damon/Documents/10_code/openSources/ws/101-pi-serial-models/repos/lerobot-main/src/lerobot/policies/pi05/modeling_pi05.py#L766)） |
| 混合损失 α=10.0 加权 | ❌ 未实现 | 无 α、无离散损失，`forward` 单一 MSE |
| 异构数据 curriculum | ❌ 未实现 | 移植版只加载训好的基座权重，不含数据管线 |

> **一句话**：`lerobot/pi05_base` 是 Physical Intelligence 用**完整两阶段（FAST 预训练 + Flow 后训练）**训好后发布的基座；lerobot 代码库拿到的是这个基座的**权重**，以及**只跑 Flow Matching 的训练/推理代码**。所以你在本地用 lerobot 做的"π₀.₅ 后训练"，本质是**在已含 FAST 预训练知识的基座上，再用 Flow Matching MSE 做任务定向**——论文里的 FAST 那一半你不会在 lerobot 里复现。

### 8.4 后训练的 LoRA 注入目标（继承 π₀，投影头名微调）

`_get_default_peft_targets`（[modeling_pi05.py L1407-1419](file:///Users/damon/Documents/10_code/openSources/ws/101-pi-serial-models/repos/lerobot-main/src/lerobot/policies/pi05/modeling_pi05.py#L1407)）：

```python
def _get_default_peft_targets(self):
    common_projections = "state_proj|action_in_proj|action_out_proj|time_mlp_in|time_mlp_out"   # L1409
    target_modules = rf"(.*\.gemma_expert\..*\.self_attn\.(q|v)_proj|model\.({common_projections}))"  # L1410
    modules_to_save = ["model.proprio_history_proj"] if self.config.use_proprioceptive_memory else []  # L1415
    return {"target_modules": target_modules, "modules_to_save": modules_to_save}
```

与 π₀ 的正则几乎相同（LoRA 只打 Expert 的 q/v_proj + 投影头，不碰 VLM 主干），差异仅在投影头名单：

| | π₀ | π₀.₅ |
|---|---|---|
| 投影头正则 | `state_proj\|action_in_proj\|action_out_proj\|action_time_mlp_in\|action_time_mlp_out` | `state_proj\|action_in_proj\|action_out_proj\|**time_mlp_in**\|**time_mlp_out**` |
| 实际存在的模块 | 5 个都在 | **`state_proj` 已删**（正则里留着是历史兼容，匹配不到）、`action_time_mlp_*`→`time_mlp_*` |
| MEM 本体投影 | 无 | `modules_to_save=["model.proprio_history_proj"]`（开启时） |

> **咬合（呼应 5.5 单向信息流）**：与 π₀ 一样，注意力是"prefix 看不到 action"的块状因果结构，梯度天然引向 Expert 侧。LoRA 只注入 `gemma_expert` 的 q/v_proj + 投影头，与信息流方向一致——冻结的 VLM 保住预训练语义，可训的 Expert 负责"把通用语义翻译成具体动作"。这就是 doc 24 里 LoRA r=16 只用 1.29M 参数就能 smoke 到 90% 的架构原因。

### 8.5 咬合：后训练如何复用第 3-6 节的内核

后训练不是另起炉灶，而是复用你已理解的全部内核：

- **数据侧**：state/action 走 6.5 的 32 维 padding、6.1 的离散化、6.2 的归一化（LIBERO 强制 MEAN_STD）、相机 -1 填充；
- **前向侧**：每个训练 step 就是第 4 节的 `forward`——采 noise/time、`_build_flow_matching_inputs` 插值 \(x_t\)、算 \(u_t\)、过双流（Expert 侧 AdaRMS 注入时间）、`mse_loss(u_t, v_t)`；
- **区别只在梯度**：LoRA 让梯度只更新 Expert 的 q/v_proj + 投影头（或 Expert-only 全解冻 Expert），VLM 主干冻结。

一句话：**π₀.₅ 后训练 = 用第 4 节的 Flow Matching 损失（无 FAST 项），在第 6 节离散化+QUANTILES/MEAN_STD 的数据上，只微调 8.4 的 Expert 侧参数**。推理时（第 3 节）加载的 checkpoint 就是这次后训练的产物。

**四个最值得记住的咬合点**：

1. **时间注入（4.5 节）**：π₀ 把时间"拼进动作 token"（cat+MLP，`adarms_cond=None`），π₀.₅ 把时间"调制每层归一化"（独立 time_mlp → AdaRMS，`use_adarms=[False,True]`）——这是 DiT 风格的自适应条件化，在**每一层**反复注入时间，比 π₀ 的输入端一次性注入更强。
2. **state 表示（5.3 + 6.1 节）**：π₀ 的 state 是 suffix 里的**连续 token**（独立 Block 2，可缓存），π₀.₅ 把它**离散成 256bin 文本塞进 prefix**（并入 Block 1）——注意力块从三块变两块，动作 token 的 cumsum 从 2 降到 1。
3. **论文 vs 代码（3.4 + 8.2 节）**：论文的**层级推理**和 **FAST 离散预训练**在 lerobot 移植版里**没有实现**——lerobot 只跑"后训练的 Flow Matching action expert"这一路。别把论文能力当成代码能力。
4. **继承不变的部分（2.1 + 4.1 + 5.1 节）**：双流融合、Flow Matching 数学、cumsum 掩码机制、KV 缓存、32 维 padding、相机 -1 填充——**π₀.₅ 与 π₀ 完全同源**，26 号文档的结论原样适用。
