## 1. 数据集输入：aloha_sim_transfer_cube_human

**数据来源**：50 条专家演示（teleoperation），每条 400 帧（fps=50，每条 8 秒），共 20,000 帧。

**磁盘目录结构**：
```
data/aloha_sim_transfer_cube_human/
├── data/chunk-000/file-000.parquet          # 1-20,000 帧的结构化数据
├── meta/info.json                            # 字段 schema（关键！）
├── meta/stats.json                           # STATE/ACTION 的 mean/std（normalizer 训练时依据）
├── meta/tasks.parquet                        # task description（全数据集同一字符串）
└── videos/observation.images.top/chunk-000/file-000.mp4   # 50×400 帧顶视 RGB 视频
```

### 1.1 info.json 的字段 schema（每一帧有这些字段）

| 字段名 | dtype | shape | 含义 |
|---|---|---|---|
| `observation.images.top` | video | `[480, 640, 3]` uint8 | 顶视角 RGB 图；parquet 里存视频索引，训练时解码 |
| `observation.state` | float32 | `[14]` | 双臂 14D 关节当前位置（rad） |
| `action` | float32 | `[14]` | 双臂 14D 下一个时间步的目标动作（rad） |
| `episode_index` | int64 | `[1]` | 本帧属于第几条 demo（0~49） |
| `frame_index` | int64 | `[1]` | 本帧在该 demo 内的帧号（0~399） |
| `timestamp` | float32 | `[1]` | 时间戳（0~8 秒） |
| `next.done` | bool | `[1]` | 是否该 demo 最后一帧 |
| `task_index` | int64 | `[1]` | 全数据集恒 = 0（单任务） |

### 1.2 14D 关节索引（**左臂在前？右臂在前？**）

在 [info.json:40-56](file:///home/creator/ws/11_pi_serial_models/data/aloha_sim_transfer_cube_human/meta/info.json#L40-L56) 的 `names.motors` 字段明确定义顺序为 **左臂 7 个 + 右臂 7 个**：

| 索引 | 关节名 | 侧 |
|---|---|---|
| 0 | left_waist | 左臂 |
| 1 | left_shoulder | 左臂 |
| 2 | left_elbow | 左臂 |
| 3 | left_forearm_roll | 左臂 |
| 4 | left_wrist_angle | 左臂 |
| 5 | left_wrist_rotate | 左臂 |
| **6** | **left_gripper** | **左夹爪（开合）** |
| 7 | right_waist | 右臂 |
| 8 | right_shoulder | 右臂 |
| 9 | right_elbow | 右臂 |
| 10 | right_forearm_roll | 右臂 |
| 11 | right_wrist_angle | 右臂 |
| 12 | right_wrist_rotate | 右臂 |
| **13** | **right_gripper** | **右夹爪（开合）** |

**注意**：之前评估中 LoRA 输出的「索引 11」其实是 **right_wrist_angle**（右臂第 4 关节），不是左臂关节——这就是为什么空 task vs 正确 task 的 cos 对比中索引 11 反向会挡住右臂抓方块的几何路径。

### 1.3 stats.json：normalizer 的依据（**训练时固化进 checkpoint**）

| 字段 | 归一化模式 | 14 个关节的 mean / std（节选） |
|---|---|---|
| `observation.state` | **MEAN_STD** | mean[6]=0.475（左夹爪）、mean[13]=0.684（右夹爪）；std[12]=0.530（右腕 rotate 方差最大） |
| `action` | **MEAN_STD** | 14 个 mean/std 与 state 数值几乎相同（因为 action 就是下一时刻的 state 增量很小） |
| `observation.images.*` | **IDENTITY** | 不做均值方差归一（模型内部会把 [0,1] 再线性缩到 [-1,1]，见 §4.1） |

```text
normalization 公式（MEAN_STD）：  x_norm = (x - mean) / (std + eps)    eps=1e-8
反归一化（postprocessor 用）：     x_denorm = x_norm * std + mean
```

### 1.4 task description（全数据集常数！）

`meta/tasks.parquet` 中每一行的 task_description 都是同一个字符串：

```
"Pick up the cube with the right arm and transfer it to the left arm."
```

由于 100% 恒定，**PI0 的语言分支（PaliGemma Gemma 2B）学不到语言条件区分**。实际训练中 language token embedding 相当于一个常数 bias，LoRA 的容量全部给了视觉+状态分支（我们做过余弦相似度验证：空 task vs 正确 task 动作输出 cos=0.98+）。

### 2.2 每个参数如何变成模型配置

| CLI 参数 | 进入哪一层配置 | 最终效果 |
|---|---|---|
| `--policy.type=pi0` | `PreTrainedConfig` 注册 → 加载 `PI0Policy` 类 | 选择 PI0（PaliGemma+扩散）模型架构，非 Diffusion Policy / ACT 等其他 policy |
| `--policy.pretrained_path=.../pi0_base` | `PI0Policy.from_pretrained()` | 加载 14GB F32 基座权重（PaliGemma 2B + Gemma 300M Expert + state/action proj 头） |
| `--policy.dtype=bfloat16` | 模型权重转换为 bf16 存 CUDA | 显存从 28GB（F32）降到 14GB（bf16）；forward 中 accumulate 仍用 F32 |
| `--peft.method_type=LORA + --peft.r=32` | PEFT wrapper 注入低秩矩阵到 target_modules | 可训参数只有 2.8M（全参 3B 的 0.09%），LoRA 目标模块见 §6.2 |
| `--steps=160000` | scheduler 总步数 + 训练主循环终止 | 20,000 帧 × 32 epoch |
| `--batch_size=4` | DataLoader batch_size + micro-batch | 每 step 4 条帧样本，5090 32GB 显存峰值 11.8GB |
| `--rename_map={...}` | PreProcessor step 0（§3） | 把数据集字段名 `observation.images.top` 改成 PI0 基座期待的 `observation.images.base_0_rgb` |
| `--wandb.mode=offline` | WandBLogger | 不联网，离线模式下把 loss/grad/lr 等写入 wandb/run-*/ 本地目录 |
| 未显式传的关键默认：`--policy.n_action_steps=50` `--policy.chunk_size=50` `--policy.num_inference_steps=10` | PI0Config | 见 §5 / §7 |

## 3. Processor 流水线：7 步预处理（每步 tensor shape 变化）

PreProcessor 流水线保存在每个 checkpoint 的 `policy_preprocessor.json`（[060000 checkpoint 版](file:///home/creator/ws/11_pi_serial_models/outputs/pi0_aloha_cube/checkpoints/060000/pretrained_model/policy_preprocessor.json)）。**训练和评估共用同一条流水线**（从 checkpoint 反序列化）。

输入 batch（从 parquet/DataLoader 取出的原始帧，batch_size=4）：
```python
{
  "observation.images.top":    Tensor [4, 3, 480, 640] float32 [0,1]   # 4 张顶视 RGB
  "observation.state":         Tensor [4, 14] float32                     # 4 条帧的当前关节
  "action":                    Tensor [4, 14] float32                     # 4 条帧的 GT 动作
  "task":                      list[str] len=4                              # 4 条帧的 task 字符串（都相同）
}
```

### Step 0: rename_observations_processor — 改名对齐

```
rename_map: {"observation.images.top" → "observation.images.base_0_rgb"}
```

输出：
```python
{
  "observation.images.base_0_rgb": Tensor [4, 3, 480, 640]   # 名字改了，值不变
  "observation.state":            Tensor [4, 14]
  "action":                       Tensor [4, 14]
  "task":                         ["...", "...", "...", "..."]
}
```

### Step 1: to_batch_processor — list[dict] → dict[Tensor]

DataLoader 的 collate_fn 输出本来已经是 dict，但这一步是保险转换：任何 list[str] / list[np] 统一 batch。这里 task 字段从 list[str] 直接保留。

### Step 2: pi0_new_line_processor — task 末尾补换行符

```python
batch["task"] = [s + "\n" for s in batch["task"]]
```

因为 PaliGemma 预训练时的 prompt 模板是 `"<image>\n<prompt>\n"`，processor 必须和它对齐。

### Step 3: tokenizer_processor — task → token ids + attention mask

Tokenizer 用的是 PaliGemma 3b-pt-224 的 Gemma 分词器（已从 ModelScope 预注入 HF 离线缓存 `~/.cache/huggingface/hub/models--google--paligemma-3b-pt-224/`）。

参数：`max_length=48, padding=right, truncation=true`

输出两个新字段：
```python
{
  # ... 之前字段不变 ...
  "observation.language.tokens":          Tensor [4, 48] int64     # 0=PAD, BOS=2, ..., "\n"=108
  "observation.language.attention_mask":  Tensor [4, 48] bool      # 有效 token=True, PAD=False
}
```

由于 task 字符串相同，每个样本都是 18 个有效 tokens（BOS+16 word tokens+EOS+\n），其余 30 个位置是 PAD(0)/mask=False。

### Step 4: device_processor — 搬到 GPU + dtype 规范化

所有 tensor `.to(device="cuda")`，float 默认转 fp32（policy 里自己再转 bf16）。

### Step 5: relative_actions_processor — （关闭）相对动作模式

`enabled=false`，**完全跳过**。若开启会把 action 转成相对于当前 state 的增量；但 PI0 用绝对动作（默认配置）。

### Step 6: normalizer_processor — STATE/ACTION 均值方差归一化

从同目录的 safetensors `policy_preprocessor_step_6_normalizer_processor.safetensors` 加载 stats。对应 §1.3 的 stats.json 数值。

```python
# 伪代码
for feature, mode in norm_map.items():  # STATE=MEAN_STD, ACTION=MEAN_STD, VISUAL=IDENTITY
    if mode == "MEAN_STD":
        batch[feature] = (batch[feature] - mean) / (std + 1e-8)
    # IDENTITY 就 pass
```

输出：
```python
{
  "observation.images.base_0_rgb": Tensor [4, 3, 480, 640] [0,1]     # IDENTITY：不变
  "observation.state":            Tensor [4, 14] 已归一（分布 ~N(0,1)）
  "action":                       Tensor [4, 14] 已归一（分布 ~N(0,1)）
  "task":                         list[str] len=4
  "observation.language.tokens":          Tensor [4, 48] int64
  "observation.language.attention_mask":  Tensor [4, 48] bool
}
```

**以上是 Processor 的完整输出 —— 这就是传给 policy.forward() / predict_action_chunk() 的 batch 协议。**

## 4. PI0 模型架构总览

PI0 是 Open π₀ 的 LeRobot 端口版，架构为「VLA（Vision-Language-Action）双流 Transformer + Flow Matching 扩散动作头」。

### 4.1 架构分层图

```
┌──────────────────────────────────────────────────────────────────────┐
│                          PI0Policy（外壳）                            │
│  ┌───────────── embed_prefix ──────────────┐  ┌── embed_suffix ────┐ │
│  │  images (base_0_rgb)                    │  │ state[14]          │ │
│  │    → PaliGemma SigLIP vision_tower      │  │   → state_proj    │ │
│  │    → (224×224, 256 tokens, D=2048)      │  │   → D=2048        │ │
│  │  task tokens[48]                         │  │ x_t[50, 32]       │ │
│  │    → Gemma Embedding                    │  │   (noisy action   │ │
│  │    → (48 tokens, D=2048)                │  │    chunk padded)  │ │
│  │  mask: 图像 token + 有效语言 token      │  │ time[1]          │ │
│  │  → 共 256+18≈274 前缀 tokens            │  │   → time_mlp     │ │
│  └───────────────────┬────────────────────┘  │   → D=2048        │ │
│                      │ 拼接 prefix+suffix    │ 50 action tokens   │ │
│                      ▼                        │ (pad到32维)       │ │
│  ┌───────────────────────────────────────────┴────────────────────┐  │
│  │    PaliGemma + Gemma Expert 双流 18 层 Transformer 融合        │  │
│  │    每层：PaliGemma Layer i 和 Gemma Expert Layer i 交替通过    │  │
│  │    compute_layer_complete() 做 cross-token 注意力（prefix 能  │  │
│  │    看到 suffix、suffix 能看到 prefix——完整双向 attention）     │  │
│  └──────────────────────────────┬─────────────────────────────────┘  │
│                                 ▼ 最后 suffix 50 tokens 的 hidden    │
│                        action_out_proj（Linear D→32）                 │
│                                 │                                      │
│                                 ▼                                      │
│                    v_t = noise - action_pred    （B,50,32）           │
│  ─────────────────────────────────────────────────────────────────── │
│  训练：MSE(u_t=noise-action_gt, v_t) → 反向                           │
│  推理：Euler 积分 10 步 从 纯 noise → 去噪 action → 返回            │
└──────────────────────────────────────────────────────────────────────┘
```

### 4.2 架构分层图逐块详解

上面这张图从上到下分成 **5 个阶段**，下面逐块解读每个矩形框里到底发生了什么、tensor shape 怎么变、哪行代码在跑。

---

#### 阶段 A：embed_prefix — 前缀嵌入（图像 + 语言）

对应代码：[`embed_prefix()`](file:///home/creator/ws/11_pi_serial_models/repos/lerobot-main/src/lerobot/policies/pi0/modeling_pi0.py#L487-L527)

图的左上角大框。它接收两类输入，把它们变成统一维度 D=2048 的 token 序列：

**A1. 图像路径**（图左上）视觉编码器（Vision Encoder）的工作流程，也就是模型"眼睛"如何把一张原始图片变成模型能理解的"视觉语言"

```
输入  images = [Tensor[B, 3, 224, 224]]   # _preprocess_images 已处理成 NCHW [-1,1]
         ↓
    self.paligemma_with_expert.embed_image(img)
         ↓  内部走 SigLIP ViT vision_tower
         ↓  patch_embed → 14×14 patch → 256 个 token
         ↓  每个 token D=2048
输出  img_emb = [B, 256, 2048]
      img_mask = [B, 256] 全 True（真实图像，非 padding）
```

SigLIP 把 224×224 的图切成 14×14 个 patch（每个 16×16 像素），每个 patch 经线性投影成 1 个 2048 维 token，再加位置嵌入 → **256 个视觉 token**。

**A2. 语言路径**（图左上右侧）

```
输入  lang_tokens = [B, 48] int64         # tokenizer_processor 已分词+padding
         ↓
    self.paligemma_with_expert.embed_language_tokens(lang_tokens)
         ↓  内部走 Gemma token embedding（nn.Embedding, vocab=256000, dim=2048）
输出  lang_emb = [B, 48, 2048]
      lang_mask = [B, 48] bool            # 有效 token=True，PAD=False
```

**A3. 拼接成完整前缀**（图左下箭头 "拼接 prefix"）

```python
embs      = cat([img_emb, lang_emb], dim=1)     # [B, 256+48=304, 2048]
pad_masks = cat([img_mask, lang_mask], dim=1)   # [B, 304]
att_masks = [0]*256 + [0]*48                    # 全 0 = 普通 bidirectional
```

所以前缀总长 **304 个 token**，其中视觉 256 + 语言 48（但实际有效语言 token 只有 18，其余 30 个是 PAD）。

图里的 `256+18≈274 前缀 tokens` 指的是 **有效 token 数**（256 视觉全有效 + 18 语言有效），但序列长度仍是 304（含 PAD）。

---

#### 阶段 B：embed_suffix — 后缀嵌入（状态 + 噪声动作 + 时间）

对应代码：[`embed_suffix()`](file:///home/creator/ws/11_pi_serial_models/repos/lerobot-main/src/lerobot/policies/pi0/modeling_pi0.py#L529-L590)

图的右上角大框。它把「当前机器人状态」和「噪声化的动作 chunk」变成和前缀同维度 D=2048 的 token：

**B1. 状态路径**（图右上最上方）

```
输入  state = [B, 32]                       # 14D 真值 pad 到 32D
         ↓
    self.state_proj = nn.Linear(32, 2048)
         ↓
输出  state_emb = [B, 2048]
      重组为 [B, 1, 2048]                    # 1 个 state token
      state_mask = [B, 1] 全 True
```

state 只占 **1 个 token**，浓缩了双臂 14 个关节当前位置（pad 后 32D）。

**B2. 时间嵌入**（图右中 "time → time_mlp"）

```
输入  time = [B] float in [0,1]              # Beta(1.5,1.0) 采样的时刻
         ↓
    create_sinusoidal_pos_embedding(time, D=2048, min_period=0.004, max_period=4.0)
         ↓  正弦余弦位置编码
输出  time_emb = [B, 2048]
```

注意 `time_emb` 会被 expand 成和 action_emb 一样的形状后参与拼接（见 B3）。

**B3. 噪声动作 + 时间融合**（图右下 "x_t → action_in_proj + time_mlp"）

```
输入  x_t = [B, 50, 32]                     # 噪声混合动作 chunk（§5.2 的 x_t = t*noise+(1-t)*action_gt）
         ↓
    self.action_in_proj = nn.Linear(32, 2048)
         ↓
    action_emb = [B, 50, 2048]
         ↓
    time_emb expand → [B, 50, 2048]         # 每个动作 token 都叠加同一个时间嵌入
         ↓
    action_time_emb = cat([action_emb, time_emb], dim=2)  # [B, 50, 4096]
         ↓
    self.action_time_mlp_in  = nn.Linear(4096, 2048) + SiLU
    self.action_time_mlp_out = nn.Linear(2048, 2048)
         ↓
输出  action_time_emb = [B, 50, 2048]       # 50 个动作 token，每个已融合时间信息
```

这 50 个 token 对应未来 1 秒（50fps）的动作序列，每个 token 都知道「我在 chunk 的哪个位置」和「当前去噪时间步 t」。

**B4. 拼接成完整后缀**

```python
embs      = cat([state_emb[None], action_time_emb], dim=1)  # [B, 1+50=51, 2048]
pad_masks = cat([state_mask, action_time_mask], dim=1)      # [B, 51]
att_masks = [1] + [0]*(chunk_size-1)                          # [1,0,0,...,0]（见下解释）
```

后缀总长 **51 个 token**（1 个 state + 50 个 action）。

> **attention mask 的关键设计**（[modeling_pi0.py:582-583](file:///home/creator/ws/11_pi_serial_models/repos/lerobot-main/src/lerobot/policies/pi0/modeling_pi0.py#L582-L583)）：`att_masks = [1] + [0]*(49)` 的含义是——**只有第 0 个 action token 能被前缀看到**，后面 49 个 action token 对前缀"不可见"。这是 openpi 的设计：让图像/语言/state 只需要关注"当前要预测的动作"，不需要关心未来 49 步的内部依赖。反过来 suffix 内部 51 个 token 互相都能 attend（双向）。

#### 阶段 C：双流 Transformer 融合（核心）

对应代码：[`compute_layer_complete()`](file:///home/creator/ws/11_pi_serial_models/repos/lerobot-main/src/lerobot/policies/pi0/modeling_pi0.py#L78-L100) + [forward L618-631](file:///home/creator/ws/11_pi_serial_models/repos/lerobot-main/src/lerobot/policies/pi0/modeling_pi0.py#L618-L631)

图的中间大框。这是 PI0 的核心创新：**两个 Transformer 并行跑，但每层之间互相交换信息**。

**C1. 拼接前缀 + 后缀 → 完整 token 序列**

```python
pad_masks = cat([prefix_pad_masks, suffix_pad_masks], dim=1)  # [B, 304+51=355]
att_masks = cat([prefix_att_masks, suffix_att_masks], dim=1)  # [B, 355]
att_2d_masks_4d = prepare_attention_masks_4d(att_2d_masks)    # [B, 1, 355, 355]
position_ids = cumsum(pad_masks) - 1                          # [B, 355] RoPE 位置 id
```

355 个 token 排成一排：**256 视觉 + 48 语言 + 1 state + 50 action**。attention mask 矩阵 355×355 决定谁能看到谁。

**C2. 双流层间融合**（[`paligemma_with_expert.forward()`](file:///home/creator/ws/11_pi_serial_models/repos/lerobot-main/src/lerobot/policies/pi0/modeling_pi0.py#L301-L400)）

```python
for layer_i in range(18):
    # PaliGemma 第 i 层 和 Gemma Expert 第 i 层 配对
    paligemma_layer = self.paligemma.model.language_model.layers[layer_i]
    gemma_expert_layer = self.gemma_expert.model.layers[layer_i]

    inputs_embeds = compute_layer_complete(
        inputs_embeds,         # [prefix_embeds, suffix_embeds] 双输入
        attention_mask,
        position_ids,
        adarms_cond,           # AdaLN 条件（PI0 中实际为 None）
        layers=(paligemma_layer, gemma_expert_layer),
        rotary_emb=rotary_emb,
    )
```

`compute_layer_complete` 内部做的事：

```
对每个 token t（1..355）：
  1. 把 t 的 embedding 分成两份：一份进 PaliGemma layer_i，一份进 Gemma Expert layer_i
  2. PaliGemma layer_i 做 self_attention → 更新前缀 token 的 hidden
  3. Gemma Expert layer_i 做 self_attention → 更新后缀 token 的 hidden
  4. 两边的 output 互相拼接回去，成为下一层的输入
```

**关键**：由于 attention 是在拼接后的 355 token 上做的（同一份 attention_mask），**PaliGemma 的视觉 token 能看到 Gemma Expert 的 action token，反之亦然**——这就是图里说的"prefix 能看到 suffix、suffix 能看到 prefix"。

> 用通俗类比：PaliGemma 是"看图说话"专家（视觉+语言理解强），Gemma Expert 是"手部控制"专家（动作时序预测强）。每层都让两个专家互相看到对方在想什么，最终融合出一个统一决策。

**C3. 为什么是 18 层？**

PaliGemma 2B 有 18 层 Gemma，Gemma Expert 300M 也有 18 层（宽度同为 2048，只是 300M 比 2B 少了些 FFN 中间维度）。所以可以一一配对。

#### 阶段 D：动作输出头

对应代码：[forward L633-641](file:///home/creator/ws/11_pi_serial_models/repos/lerobot-main/src/lerobot/policies/pi0/modeling_pi0.py#L633-L641)

图的下部，Transformer 输出后的处理：

```
suffix_out = Transformer output                     # [B, 355, 2048]（355 个 token 的最终 hidden）
         ↓
    suffix_out[:, -chunk_size:]                      # 只取最后 50 个 token（动作 token 的 hidden）
         ↓                                          # [B, 50, 2048]
    self.action_out_proj = nn.Linear(2048, 32)
         ↓
    v_t = action_out_proj(suffix_out)                # [B, 50, 32]
```

**为什么只取最后 50 个？** 因为前 305 个 token（256 视觉 + 48 语言 + 1 state）已经完成了"理解场景"的使命，它们的 hidden 不需要再变成动作。只有最后 50 个 action token 的 hidden 才需要投影成 32D 动作预测。

**为什么不直接取 14D？** 因为 `max_action_dim=32`，前 14 维是真实动作，后 18 维是 pad。`action_out_proj` 一次性输出 32D，后续在 `forward()` 里 truncate 到 14D（[L1117](file:///home/creator/ws/11_pi_serial_models/repos/lerobot-main/src/lerobot/policies/pi0/modeling_pi0.py#L1117)）。

#### 阶段 E：Flow Matching 训练/推理分叉

图的底部"训练 vs 推理"分叉线，是 PI0 最核心的机制：

**E1. 训练时**（[forward L592-641](file:///home/creator/ws/11_pi_serial_models/repos/lerobot-main/src/lerobot/policies/pi0/modeling_pi0.py#L592-L641)）

```python
# 采样噪声和时间
noise = sample_noise(actions.shape)              # [B, 50, 32] 纯高斯
time  = sample_time_beta(B)                     # [B] Beta(1.5,1.0) 分布

# 线性插值混合 GT 和噪声 → noisy action
x_t = time * noise + (1 - time) * actions      # t=1 时纯噪声，t=0 时纯 GT

# 预测目标：速度场 u_t = noise - actions
u_t = noise - actions

# 模型预测 v_t（从 x_t 出发，经 Transformer 融合后由 action_out_proj 输出）
v_t = Transformer(x_t, images, lang, state, time)

# loss
loss = MSE(u_t, v_t)                             # 让模型学会预测"从 x_t 到 GT 的方向"
```

**E2. 推理时**（[`sample_actions()` L644-720](file:///home/creator/ws/11_pi_serial_models/repos/lerobot-main/src/lerobot/policies/pi0/modeling_pi0.py#L644-L720)）

```python
x_t = randn(B, 50, 32)                          # 纯噪声起点（t=1）
for k in range(10):                             # num_inference_steps=10
    t_k = 1.0 - k / 10                          # t 从 1.0 → 0.0
    v_t = Transformer(x_t, images, lang, state, t_k)  # 模型预测当前速度
    x_t = x_t + dt * v_t                        # Euler 积分一步
return x_t                                      # 最终的 x_t ≈ GT action
```

**直觉理解**：训练时模型学会了"给定任何 noisy action x_t 和时间 t，预测从 x_t 到真实 action 的方向 v_t"。推理时从纯噪声出发，反复问模型"往哪走？"走 10 步就到真实动作了。这就是 Flow Matching —— **把噪声到动作的路径建模成一个连续速度场，然后用 Euler 积分沿这个场走**。

#### 关键：为什么 prefix 和 suffix 用两个 Transformer 而不是一个？

| 设计选择 | 好处 | 代价 |
|---|---|---|
| 单一大 Transformer（355 token 一起跑） | 简单 | 3B 参数全参微调成本高；视觉/语言 token 占 85%，挤占动作 token 的梯度信号 |
| **双流**（PaliGemma 2B + Gemma Expert 300M，图这种） | 1) 基座 PaliGemma 可冻结只训 Expert；2) Expert 专注动作时序，梯度信号纯净；3) 参数量 2B+300M > 单 3B，但有效"动作容量"更高 | 架构复杂；两层间要同步交换 hidden |

PI0 选了双流 + LoRA 只微调 Expert 的 Q/V proj + 动作头 —— 这就是为什么你 r=16 (1.4M 可训参数) 就能让右臂学会抓方块：动作专家的全部容量都给了动作时序，没浪费在视觉理解上。

### Step 5.1: 预处理输入 → 拆 4 条并行路径

#### a) 图像路径：`_preprocess_images()` [modeling_pi0.py:983-1046](file:///home/creator/ws/11_pi_serial_models/repos/lerobot-main/src/lerobot/policies/pi0/modeling_pi0.py#L983-L1046)

#### d) 动作路径：`prepare_action()` → 14D pad 到 32D × chunk_size

**注意**：Processor 的 step6 归一化后 batch["action"] 只有 [B, 14]，但 flow matching 需要在 **时序维度** 上预测 chunk_size=50 的动作。训练中 `prepare_action()` 会从 Dataset 的 `pad_vector + 时序偏移采样` 逻辑（EpisodeAwareSampler 从某 frame_index 起连续取 50 帧的 action，pad 成 [B, 50, 32]）。

```python

```

### Step 5.2: Flow Matching 采样 noise & time

```python
noise = sample_noise(actions.shape)   # [B, 50, 32] N(0,1)  # 纯高斯
time  = sample_time_beta(B)          # [B,]  Beta(1.5, 1.0) → [0,1] 分布偏 t≈1
```

然后线性插值做 "noisy action" x_t（[modeling_pi0.py:594-596](file:///home/creator/ws/11_pi_serial_models/repos/lerobot-main/src/lerobot/policies/pi0/modeling_pi0.py#L594-L596)）：

```python
time_expanded = time[:, None, None]         # [B, 1, 1]
x_t = time_expanded * noise + (1 - time_expanded) * actions   # [B, 50, 32] 噪声和 GT 的线性混合
u_t = noise - actions                                         # 预测目标："去噪速度"
```

### Step 5.3: embed_prefix — 图像+语言嵌入融合

```python

```

内部流程：
1. images 喂给 **PaliGemma SigLIP ViT vision_tower**：[B, 3, 224, 224] → 256 个 tokens × D=2048
2. lang_tokens 喂给 **Gemma token embedding**：[B, 48] → 48 tokens × D=2048
3. 图像 token + 语言 token **按顺序拼接**：`[B, 256+48=304, 2048]` → prefix_embs
4. prefix_pad_masks = 图像位置全 True + 语言 mask 位（有效 18 True + 30 PAD False）

### Step 5.4: embed_suffix — 状态 + 噪声动作 + 时间嵌入

```python
suffix_embs, suffix_pad_masks, suffix_att_masks, adarms_cond = embed_suffix(state, x_t, time)
```

内部流程：
1. state[B, 32] → **state_proj Linear 32→2048** → 1 个 token → `[B, 1, 2048]`
2. x_t[B, 50, 32] → **action_in_proj Linear 32→2048** → 50 个 tokens → `[B, 50, 2048]`
3. time[B,] → **action_time_mlp_in + action_time_mlp_out**（Fourier + MLP 位置嵌入）→ adarms_cond 作为 AdaLM 条件加到每层 LN 上
4. 拼接：state token + 50 action tokens → suffix_embs `[B, 51, 2048]`
5. suffix_pad_masks = `[B, 51]` 全 True（state+50 action 都有效）

### Step 5.5: Transformer 融合（双流 18 层）

```python
pad_masks = cat([prefix_pad_masks, suffix_pad_masks], 1)    # [B, 304+51=355]
att_masks = cat([prefix_att_masks, suffix_att_masks], 1)
att_2d_masks_4d = prepare_attention_masks_4d(att_masks)    # [B, 1, 355, 355]
position_ids = cumsum(pad_masks) - 1                       # [B, 355] RoPE 位置 id

suffix_out = paligemma_with_expert.forward(
    inputs_embeds=[prefix_embs, suffix_embs],   # 双输入
    attention_mask=att_2d_masks_4d,
    position_ids=position_ids,
)
```

**双流融合的核心秘密**：`compute_layer_complete` 对每层（zip(PaliGemma 第 i 层, Gemma Expert 第 i 层)）做：

> prefix 和 suffix 拼接成统一 token 序列，每一层 self-attention 让图像 tokens 看到动作 tokens、动作 tokens 看到语言 tokens——**完整的双向 cross-modal attention**。这就是为什么 PI0 能做 VLA：视觉/语言/状态/动作所有模态在同一 attention 空间内互相条件。

由于 LoRA 会插入 target_modules（§6.2），反向传播只更新这些 LoRA 低秩矩阵。

### Step 5.6: 动作输出头 + loss

```python
suffix_out = suffix_out[:, -chunk_size:]     # [B, 50, D] 只取最后 50 个动作 token 的 hidden

losses = losses[:, :, :14]                   # truncate 到原始 14D（后 18 个 pad 维度不参与 loss）

```

**训练目标**：预测的 v_t（noise - action）和 GT u_t 接近。Flow matching 训练完后，推理时从纯 noise 做 Euler 积分去噪，就能得到 action。

```python
def run_one_episode(env, policy, preprocessor, postprocessor, seed):
    obs, _ = env.reset(seed=seed)        # obs 是 dict
    # obs["pixels/top"]       → [1, 480, 640, 3] uint8（vec env，batch=1）
    # obs["agent_pos"]       → [1, 14] float32（关节位置）

    # Step A：获取 task（[lerobot_eval.py:280-286] 三级 fallback，当前是第③级）
    try:
        task_list = env.call("task_description")   # ①
    except:
        try:
            task_list = env.call("task")            # ②
        except:
            task_list = [""] * env.num_envs         # ③ 当前用的（gym_aloha 没加属性）
    obs["task"] = task_list

    # Step B：rename_map 对齐（和训练 step0 一样）
    obs = rename_batch_keys(obs, {"observation.images.top":"observation.images.base_0_rgb",
                                  "pixels/top":             "observation.images.base_0_rgb",
                                  "agent_pos":              "observation.state"})

    sum_reward = 0.0
    max_reward = 0.0
    frames = []

    policy.reset_action_queue()   # 清空 50 步 action queue（§7.3）

    for step in range(400):
        # 1. Preprocess 输入（和训练 §3 完全一致！）
        batch = preprocessor(obs)           # 7 步：rename→to_batch→newline→tokenizer→
                                            #       device→(skip relative)→normalizer
        # batch 最后包含：images/base_0_rgb, state, language.tokens, language.masks

        # 2. 推理出动作 chunk（[modeling_pi0.py:1059-1092](file://.../modeling_pi0.py#L1059-L1092)）
        if len(policy._action_queue) == 0:
            actions_chunk = policy.predict_action_chunk(batch)   # [1, 50, 14] 归一化空间
            # predict_action_chunk 内部做 Euler 积分 10 步（Flow Matching 去噪）
            policy._action_queue.extend(actions_chunk[:, 0, :], ...)  # 50 步进队

        action_norm = policy._action_queue.popleft()   # [1, 14]（取 chunk 的第 0 步）

        # 3. Postprocess → 反归一化（把 ~N(0,1) 变回关节 rad 值域）
        action_real = postprocessor(action_norm)    # [1, 14]

        # 4. env.step
        obs, reward, terminated, truncated, info = env.step(action_real)
        sum_reward += float(reward)
        max_reward = max(max_reward, float(reward))
        frames.append(env.render("rgb_array"))      # 存 mp4

    success = (max_reward >= 4)       # reward 阶梯：§7.4
    return {"sum_reward": sum_reward, "max_reward": max_reward,
            "success": success, "video": frames}
```

### 7.3 predict_action_chunk 推理内部（和 §5 训练 forward 的关键区别）

训练是 forward(x_t) → 预测 u_t=noise-action → MSE loss。**推理是反向过程**：从纯高斯噪声开始，用 Euler 积分走 `num_inference_steps=10` 步去噪，得到最终 action chunk：

```python
# 伪代码（sample_actions，[modeling_pi0.py:644-720](file:///home/creator/ws/11_pi_serial_models/repos/lerobot-main/src/lerobot/policies/pi0/modeling_pi0.py#L644-L720)）
x_t = randn(B, chunk_size=50, max_action_dim=32)   # 纯噪声

for k in range(num_inference_steps):
    # 离散时间：t_0=1.0 → t_9≈0.004
    time_k = 1.0 - k / num_inference_steps
    time_tensor = full(B, time_k)

    # 用同一个 Transformer 模型（prefix=suffix 和训练完全同结构）预测速度 v_t
    prefix_embs, ... = embed_prefix(images, lang_tokens, ...)
    suffix_embs, ... = embed_suffix(state, x_t, time_tensor)
    suffix_out = Transformer(prefix, suffix)
    v_t = action_out_proj(suffix_out[:, -50:])      # [B, 50, 32]

    # Euler 步：x_{t - Δt} = x_t + Δt * v_t
    dt = time_k - (1.0 - (k+1) / num_inference_steps)
    x_t = x_t + dt * v_t

return x_t   # [B, 50, 14]（truncate 到 14D，已在归一化空间）
```

这就是 Flow Matching 推理——**把训练时学的"速度场 v_t"沿时间积分从 t=1→t=0**，从纯噪声轨迹到动作轨迹。10 步是 LeRobot 默认，精度/速度平衡。

**Action Queue 的作用**：为什么 `select_action` 不每步都 `predict_action_chunk`？因为 chunk_size=50 预测未来 1 秒动作，**第 0 步一次性拿到 50 步**，接下来 49 步直接 dequeue 就行，避免重复推理 50 次浪费算力。这就是为什么评估每步只有 ~20ms 推理延迟但每秒 ~10 episode/s。

### 7.4 reward 阶梯 & success 判定

[AlohaTransferCube 任务 reward 逻辑](file:///home/creator/ws/11_pi_serial_models/.venv312/lib/python3.12/site-packages/gym_aloha/tasks/sim.py#L125-L149)：

| step reward | 条件 | 阶段 |
|---|---|---|
| 0 | 其他 | 无 |
| 1 | 右爪末端接触方块（cube 接触） | 第一步 |
| 2 | 右爪抓住方块（夹爪闭合 + 方块 > 桌面高度阈值）→ 持住每步都给 2 | **你当前上限**（50 次评估 30% 到达） |
| 3 | 左爪末端接触方块 → 交接开始 | **从未到达** |
| 4 | 左爪抓住方块 + 方块 > 桌面高度阈值 → success=True | 最终目标（=success） |

由于 **step reward**，如果一个 episode 里从第 150 步到第 350 步一直 reward=2（持住方块 200 步），sum_reward = 200 × 2 = 400。这就是你 50 次评估里 ep2 sum=436 的原因——右爪成功持住了方块 218 步，但之后掉了没递到左爪（max 仍然只有 2）。

## 8. 训练 vs 评估 pipeline 的关键差异点

| 方面 | 训练（1 step） | 评估（一个 env step） |
|---|---|---|
| **action 来源** | Dataset 中连续 50 帧 GT action（教师强制） | policy 推理 Euler 积分 10 步（闭环执行） |
| **batch["action"] 是否存在** | ✓ 有（用来算 MSE loss） | ✗ 无（只有 obs，不需要 GT） |
| **Noise & Time 采样** | 随机 sample（flow matching 训练） | 固定 Euler 10 步：t=1.0→0.0（不采样 time） |
| **模型输出** | v_t：噪声速度 | x_t=0：最终去噪 action chunk |
| **loss 计算** | ✓ MSE(u_t, v_t) + backward + AdamW | ✗ 只有 forward，无 grad（torch.no_grad） |
| **processor pipeline** | 相同！7 步流水线 → 同一个 batch 协议 | 相同！同一个 pipeline（从 checkpoint 反序列化加载同一份 processor.json + stats） |
| **动作时序使用** | 一整个 batch 50 帧一起算 loss | predict 出 50 步后只取第 0 步执行，剩余 49 步缓存 action_queue |
| **dtype** | 权重 bf16，forward accumulate F32（AMP 默认关闭） | 同（bf16 权重 + F32 accumulation） |
| **normalizer stats** | 用 stats.json 的 mean/std 归一化 STATE/ACTION 到 ~N(0,1) | 同 preprocessor，多了 postprocessor 反归一化到真实关节值域再 env.step |
| **task 获取路径** | 直接读 tasks.parquet（每条帧自带 task_index→task_description） | env.call("task_description"/"task") 三级 fallback（当前走第③级） |
| **图像来源** | parquet 解码 mp4 → [480,640,3] → 存入 DataLoader | env.render / MuJoCo 渲染 → [480,640,3] RGB → obs dict |
| **随机初始化** | 每条 demo 的真实第一帧 | MuJoCo 随机 seed+方块位置（初始 state 由 reset() 决定） |
