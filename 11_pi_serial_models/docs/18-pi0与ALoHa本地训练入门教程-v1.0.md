## 一、概念扫盲：先搞懂这些词

### 1.1 什么是模仿学习（Imitation Learning）

教小孩系鞋带，最直接的方式是**示范给他看，让他照着做**。模仿学习就是把这套方法搬到机器人上：

1. 人类先操控机器人完成若干次任务（比如 50 次"搬运方块"），全程记录"看到了什么画面"和"做了什么动作"；
2. 用这些记录训练一个模型，让它学会"给定当前画面，输出该做的动作"；
3. 之后机器人自己看画面、自己决策，不再需要人类操控。

我们用的数据集 `aloha_sim_transfer_cube_human` 名字里带 `human`，就是因为它是**人类示范**的数据。

### 1.2 什么是 VLA 模型

传统机器人程序靠工程师手写规则（"先移动到这里，再张开夹爪……"），换个任务就要重写。**VLA（Vision-Language-Action，视觉-语言-动作）模型**改变了这个范式：

```
输入：摄像头画面（Vision） + 任务指令文本（Language，如"把方块递给另一只手"）
输出：机器人下一步的动作（Action，每个关节该转多少）
```

它本质上是一个在海量机器人数据上**预训练**过的大模型，已经见过千万级的"画面→动作"例子，具备通用的手眼协调能力。我们拿到手后不需要从零教它，只需用自己的少量数据**微调（fine-tune）**，让它适应特定任务——这就是后面"训练"环节做的事。

### 1.3 π₀（pi-zero）是谁，身体里有什么

π₀ 是 Physical Intelligence 公司 2024 年发布的 VLA 模型，我们的基座模型实测共 **40 亿参数（4B）**。它的身体可以拆成两半：

```
                    ┌─────────────────────────────┐
  摄像头画面 ────→  │  PaliGemma（眼睛 + 大脑）      │
                    │  · SigLIP 视觉塔：把画面变成特征 │
  任务指令  ────→  │  · Gemma 2B 语言模型：理解任务   │
                    └──────────────┬──────────────┘
                                   │ 语义特征
                    ┌──────────────▼──────────────┐
                    │  Action Expert（运动小脑，300M）│
                    │  专门负责把"理解"翻译成"动作"     │
                    └──────────────┬──────────────┘
                                   ↓
                          14 维动作（双臂 14 个关节）
```

- **PaliGemma**：Google 的视觉-语言模型，负责"看懂画面、听懂指令"。它来自通用互联网数据预训练，没见过机器人；
- **Action Expert**：π₀ 特有的小网络（约 300M 参数），专门在机器人数据上训练，负责输出连续、平滑的动作。

**横向对比：其他机器人大模型是怎么搭"大脑 + 手"的？**

π₀ 不是唯一的 VLA 模型，各家在"眼睛大脑"和"动作输出"上的选型各不相同：

| 模型 | 视觉-语言基座（眼睛+大脑） | 动作生成器（手） | 动作输出方式 |
|------|--------------------------|------------------|----------------|
| **RT-2**（Google，2023） | PaLI-X / PaLM-E（最大 55B） | 无，LLM 亲自上 | 把动作离散成 256 档的"词"，LLM 逐 token 吐 |
| **OpenVLA**（Stanford，2024） | Prismatic（SigLIP+DinoV2 双视觉 + Llama-2 7B） | 无，LLM 亲自上 | 同样离散成 256 档 token |
| **Octo**（UC Berkeley，2024） | Transformer 编码器 | 扩散头（diffusion head） | 连续动作，扩散生成 |
| **GR00T N1**（NVIDIA，2025） | Eagle-2 VLM | 扩散 Transformer（DiT） | 连续动作，扩散生成 |
| **SmolVLA**（HuggingFace，2025） | SmolVLM-2（256M 小型 VLM） | flow matching 专家 | 连续动作，与 π₀ 同源 |
| **π₀**（本项目） | PaliGemma（SigLIP 视觉塔 + Gemma 2B） | Action Expert（300M） | 连续动作，flow matching 生成 |

可以看出两大流派，用一个类比理解：

- **"学者亲自干体力活"派（RT-2、OpenVLA）**：把每个关节的连续角度砍成 256 档，当成词汇表里的"词"，让语言模型像写句子一样一个词一个词吐动作。好处是可以直接复用现成 LLM；代价是离散化损失精度（好比用"大概十点钟方向"代替精确坐标），且大模型逐 token 生成慢；
- **"学者出主意 + 专业技师动手"派（π₀、Octo、GR00T N1）**：语言模型只负责把画面和指令压缩成"语义理解"，交给一个小型专用网络输出连续的浮点动作。π₀ 的 Action Expert 用的 flow matching（下一小节详述）正是这条路线里的具体做法。

> 顺便解释了本工作区另一个项目的关系：OpenVLA（见 `10_openVLA/`）属于第一派，π₀ 属于第二派——这也是为什么 π₀ 的动作天然平滑、而 OpenVLA 需要额外的反归一化/平滑处理。

**为什么不直接让大模型输出动作？** 因为语言模型擅长输出"词"（离散），而机器人动作是连续的浮点数（关节角度），需要一个专门的部件来做这件事。

### 1.4 Flow Matching：π₀ 怎么"生成"动作

Action Expert 输出动作的方式借鉴了图像生成领域的**扩散/流匹配**思想：

> 想象你要画一条从起点到终点的路线。Flow matching 训练模型学会"从一团乱麻（随机噪声）出发，沿着学到的'流向'，一步步修正成正确的动作"。

对初学者只需记住两点：

1. 训练时，模型反复练习"把加了噪声的动作还原成真实动作"，**loss 就是这个还原误差**（所以初始 loss ≈ 1.0，越小代表还原越准）；
2. 推理时，模型从噪声出发做 10 次左右的迭代修正，得到最终动作——这就是为什么 π₀ 推理比普通模型稍慢。

**深入三问（常见困惑，源码依据均已标注）**

**Q1：训练时为什么要加噪声？加的是什么噪声？**

因为 flow matching 学的不是"直接输出动作"，而是一个**指路系统**：给它任意一个"噪声与真实动作的混合态"，它都能指出"朝真实动作走的方向"。要练出这个本领，训练必须覆盖从"纯噪声（t=1）"到"干净动作（t=0）"的所有混合阶段——噪声就是用来构造这些**无穷多练习题起点**的。源码实证（`modeling_pi0.py` L595-596）：

```python
x_t = t * noise + (1 - t) * actions   # 混合态：t 越大噪声越多，题目越难
u_t = noise - actions                  # 标准答案：从混合态指向真实动作的"速度"
```

噪声本身是**标准高斯噪声 N(0,1)**（`sample_noise`：与 14 维动作同形状、各维独立）；混合比例 t 从 Beta 分布随机采样（openpi 惯例），保证各种难度的题目都练到。类比学导航：不能只练"从家出发怎么去公司"，还得练"从全城任意角落怎么去公司"——噪声就是那个随机出发点。

**Q2：噪声是不是越复杂越好？"能还原真实动作"到底厉害在哪？**

恰恰相反。高斯噪声 + 线性插值构成的路径**接近直线**，这正是 flow matching（rectified flow 流派）的设计目标——路径越直，推理时走越少的步数就能到终点；换复杂噪声会让路径变弯，反而需要几十上百步积分才能走准，得不偿失。

另外注意：训练时模型每步只做一件事——在某个 t 处预测"速度方向"（一步回归，loss = 预测方向与真实方向的均方误差）。它真正厉害的地方是**所有 t 处的局部方向都准**，推理时把这些方向串起来积分，才能从纯噪声一路走到真实动作。所以"能还原"是无数个局部小本领的叠加，不是一步到位的魔法。

**Q3：推理为什么只迭代 10 次？20 次、100 次不行吗？"一次迭代"是什么？**

"一次迭代" = 一次欧拉积分步：当前动作估计 x → 模型报方向 v → 走一小步 `x ← x + dt × v`（dt = 1/10）。默认 `num_inference_steps=10`（`configuration_pi0.py` L44）。

**20/100 次完全可以改**（改这个配置即可），但收益递减：学到的路径近似直线，直线分 10 段走已经很准，分 100 段不会更准，只会让推理延迟翻 10 倍——而机器人是 50Hz 实时控制，推理必须快。经典扩散模型（如 Stable Diffusion）需要几十上百步，正是因为它们学到的路径是弯的。类比：导航路线是一条笔直的高速路，分 10 段确认方向就够准，分 100 段不会更近、只会白烧油。

**数值例子：徒手算一遍 loss（把 14 维动作缩成 1 维，只看"夹爪开合度"）**

设真实动作 \(a = 3.0\)。

训练的一个步分三步：

1. **出题**：随机抽噪声 \(\varepsilon = 5.0\)、抽混合比例 \(t = 0.6\)，构造混合态
   \[x_t = 0.6 \times 5.0 + 0.4 \times 3.0 = 4.2\]
   模型看到的就是 4.2，并被告知"现在 t=0.6"；
2. **标准答案**：真实速度场 \(u = \varepsilon - a = 5.0 - 3.0 = 2.0\)（源码的 `u_t = noise - actions`）；
3. **算 loss**：假设模型预测速度 \(v = 1.7\)，则
   \[\text{loss} = (2.0 - 1.7)^2 = 0.09\]
   预测得越准 loss 越接近 0。**loss 就是"报方向"的误差**——真实方向是 2.0，模型报了 1.7，偏差 0.3，平方后 0.09。实际的 14 维动作就是对 14 个这样的方向误差取平均。

顺带解开"为什么初始 loss ≈ 1.0"：训练刚开始时模型随机初始化、输出近似 0，而标准答案 \(u = \varepsilon - a\) 里 \(\varepsilon\) 本身方差就是 1，所以 \(\text{loss}_{初始} \approx E[(u-0)^2] \approx 1\)——**不是巧合，是数学必然**；之后 loss 下降就代表模型指路越来越准。

推理 = 把方向串起来走。从纯噪声 \(x = 5.0\) 出发，朝真实动作的方向是 \(-u = -2.0\)，分 10 步（每步 dt=0.1）：

| 迭代 | 位置 x | 更新 `x ← x + dt×方向` |
|------|--------|------------------------|
| 第 1 步 | 5.0 | 5.0 + 0.1×(−2.0) = 4.8 |
| 第 2 步 | 4.8 | → 4.6 |
| …… | …… | …… |
| 第 10 步 | 3.2 | → **3.0 ✓ 到达真实动作** |

注意这个例子里路径是直线，其实 1 步也能到（5.0 + 1×(−2.0) = 3.0）；真实模型需要 10 步，是因为 14 维空间里的速度场略有弯曲，每小步要重新问一次方向。

> 类比：大雾天去目的地，手里没地图，只有一个"问路人"（模型）。**训练** = 在全城各个位置反复考问路人"现在该往哪走"，loss 就是他指错的角度；**推理** = 从随机地点出发，每走一小段问一次，直到抵达。loss 低 = 问路人在任何位置指路都准 = 你总能走到终点。

### 1.5 动作块（Action Chunk）：一次想 50 步

π₀ 每看一帧画面，不是输出 1 个动作，而是**一口气输出未来 50 步动作**（chunk_size=50，本项目 `n_action_steps=50`）。好比老司机过弯前已经想好了接下来一整段方向盘轨迹，而不是每秒现想一下。好处是动作连贯、不抖动。

### 1.6 LoRA：我们为什么只训 0.03% 的参数

全参数微调 4B 模型需要约 50GB 显存（见部署指南 5.1 决策表），单卡放不下。**LoRA（Low-Rank Adaptation）**的思路是：

> 冻结原模型全部参数，只在关键层旁边插入一对小型"适配矩阵"，训练时只更新这些小矩阵。

本项目实测：可训练参数从 4,029,405,456（4B）降到 **1,385,984（1.4M）**，只有 0.03%，显存从放不下变成 15GB 轻松跑，且小数据集上效果与全参数微调相差无几。

**0.03% 是怎么来的？对应哪些调节参数？**

0.03% 不是直接"选"出来的，而是两个参数相乘**算**出来的，命令行上对应 `--peft.*`：

| 参数 | 命令写法 | 作用 | 本项目取值 |
|------|----------|------|-----------|
| **target_modules（改哪些层）** | `--peft.target_modules`（不传则用策略默认） | 决定适配器插在哪些层，影响最大 | 默认：只改 Action Expert |
| **r（适配器宽度，即秩）** | `--peft.r=16` | 每个目标层插入 A(d×r)、B(r×d) 两个小矩阵，参数量 ∝ r | 16（官方默认折中值） |
| lora_alpha（适配器生效强度） | `--peft.lora_alpha` | 控制 LoRA 输出叠加回主干的权重 | 不传，用 peft 默认，初学不必碰 |

π₀ 的默认 target_modules（源码 `modeling_pi0.py` L1134 实测）是一个正则表达式，翻译成人话：

```
① Action Expert 所有注意力层的 Q/V 投影（gemma_expert…self_attn 的 q_proj/v_proj）
② 状态与动作的 5 个进出投影层（state_proj、action_in_proj、action_out_proj、action_time_mlp 两层）
③ PaliGemma（3B 视觉语言大脑）：一个参数都不碰
```

这个"只改手、不改脑"的选择是刻意的 VLA 微调哲学：新任务只需学新的"手上功夫"，不需要改动大脑的通用理解；而且 50 条小数据也不够动 VLM，动了反而容易把预训练学到的通用能力训坏（灾难性遗忘）。两者相乘：Action Expert 实测 18 层（gemma_300m，宽度 1024）× 每层 Q/V 两个适配器（2×16×1024 ≈ 3.3 万参数）≈ 119 万，再加进出投影层的约 20 万，合计 ≈ 1.4M = 4B 的 0.03%。

**调参讲究（什么时候动它）**：

| 症状 / 目标 | 怎么调 |
|-------------|--------|
| 欠拟合（loss 降不下去）且数据量充足 | r 升到 32/64，增大表达力 |
| 过拟合（训练 loss 很低但 rollout 成功率差） | r 降到 8/4，减少可训参数 |
| 视觉场景与预训练差异极大，想连"大脑"一起微调 | 手动给 `--peft.target_modules` 加入 PaliGemma 的层；小数据集慎用 |
| 拿不准 | 保持默认 r=16 + 默认 target_modules，本项目已验证可收敛 |

> r 的常用范围是 4~64；每翻倍 r，可训参数约翻倍（本项目 r=16 时 1.4M，r=64 约 5.5M，仍不到总参数的 0.15%）。

### 1.7 ALoHa 是什么

ALoHa（A Low-cost Open-source Hardware system for bimanual teleoperation）是一套开源**双臂遥操作**硬件标准。围绕它有一个仿真环境 `gym-aloha`，本教程的任务是其中的：

> **AlohaTransferCube-v0**：左臂把红色方块夹起，递交给右臂，右臂接住并放到指定位置。

为什么选它：任务难度适中（比单臂抓取难、比家务任务简单）、数据官方开源、仿真环境一条命令安装，是入门 VLA 微调的经典任务。

### 1.8 术语速查表

| 术语 | 人话解释 |
|------|----------|
| episode | 一段完整的任务录像（从开始到成功放下方块），本数据集共 50 段 |
| frame | 一帧画面 + 一帧动作记录，每段 episode 400 帧，共 20000 帧 |
| observation | 机器人的"感知"：摄像头画面 + 自身关节角度 |
| action | 14 维浮点向量：左右臂各 6 个关节 + 1 个夹爪 |
| 微调（fine-tune） | 在预训练模型基础上，用自己的数据继续训练 |
| LoRA | 只训练插入的小型适配矩阵，冻结原模型 |
| rollout | 让训练好的模型在仿真里"独立考试"，完整跑一遍任务 |
| checkpoint | 训练中途/结束时保存的模型权重快照 |
| batch size | 每步训练同时喂给模型的样本数，越大梯度越稳、显存占用越高 |
| epoch | 把整个数据集完整看一遍。20000 步 × batch8 ÷ 20000 帧 ≈ 8 个 epoch |

## 四、阶段 1：理解数据集

### 4.1 数据集里到底有什么

```
data/aloha_sim_transfer_cube_human/
├── meta/
│   ├── info.json        # 数据集"身份证"：格式版本、帧数、各字段的形状与类型
│   ├── episodes.jsonl   # 每段 episode 的长度与任务描述
│   ├── tasks.parquet    # 任务文本列表（"把方块递给另一只手"）
│   └── stats.json       # 各字段的均值/方差（用于归一化）
├── data/                # 每一帧的低维数据（parquet 格式）
│   └── chunk-000/episode_000000.parquet ...
└── videos/              # 每一帧的画面（mp4 视频）
    └── observation.images.top/episode_000000.mp4 ...
```

关键数字（本机实测）：

- **50 段 episode × 每段 400 帧 = 20000 帧**；
- 每帧包含：1 个顶部摄像头画面（480×640×3）、14 维关节状态（`observation.state`）、14 维动作（`action`）；
- 控制频率 50Hz，即每段演示 8 秒钟。

### 4.2 亲手加载，眼见为实

运行验证脚本（部署指南 4.3 节）：

```bash
python scripts/test_dataset.py
```

实测输出：

```
episodes: 50 | frames: 20000
action shape: [14], image shape: [3, 480, 640]
```

这一步的意义：LeRobot 框架用 `LeRobotDataset` 类把 parquet + mp4 统一成 PyTorch 可消费的样本，训练时 dataloader 每步从这里随机抽取若干帧（不是整段视频，而是**随机抽帧**——模仿学习把每帧都当作独立的"画面→动作"学习样本）。

### 4.3 关键概念：rename_map 为什么必须存在

这是初学者最容易迷糊的点。**基座模型和数据集给摄像头起的名字不一样**：

| | 图像字段的键名 |
|---|---|
| π₀ 基座（预训练时见过） | `observation.images.base_0_rgb` |
| ALoHa 数据集 | `observation.images.top` |

模型内部按名字找输入，名字对不上就直接报错。解决办法不是改数据，而是训练时传一张"改名表"：

```bash
--rename_map='{"observation.images.top":"observation.images.base_0_rgb"}'
```

> 类比：你的充电器是 Type-C 口，基座模型只认 Lightning 口，rename_map 就是那个转接头。

同理，数据集的 14 维 state/action 会被**自动 pad 到基座的 32 维**（基座在多机器人混合数据上预训练，预留了更宽的接口），无需手动处理。

## 五、阶段 2：训练——两段式设计

### 5.1 训练命令逐行讲解

训练统一通过封装脚本 `scripts/train_pi0.sh` 启动，先看它内部真正执行的 `lerobot-train` 命令（部署指南 5.2 节有逐项实测校验），每一行在做什么：

```bash
lerobot-train \
  --dataset.repo_id=aloha_sim_transfer_cube_human \   # 数据集身份标识（写进 checkpoint 元信息）
  --dataset.root=data/aloha_sim_transfer_cube_human \ # 数据集目录本身（含 meta/info.json）
  --output_dir=outputs/pi0_aloha_cube \               # 训练产物输出地（checkpoint/日志/配置）
  --job_name=pi0_aloha_cube \                         # 实验名（日志与 wandb 里显示）
  --policy.type=pi0 \                                 # 选择 π₀ 策略（而非 act/smolvla 等其他 16 种）
  --policy.pretrained_path=models/pi0_base \          # ★ 从基座权重开始微调（不传则从零训练）
  --policy.dtype=bfloat16 \                           # 权重用 bf16 存储计算，显存减半，5090 原生支持
  --policy.device=cuda \                              # 用 GPU
  --policy.push_to_hub=false \                        # ★ 不上传 HuggingFace（国内必加，否则报错）
  --wandb.enable=false \                              # 不开实验跟踪平台，避免联网
  --rename_map='{"observation.images.top":"observation.images.base_0_rgb"}' \  # 摄像头改名转接头（4.3 节）
  --peft.method_type=LORA \                           # ★ 启用 LoRA（1.6 节）
  --peft.r=16 \                                       # LoRA 秩：适配矩阵的宽度，16 是常用折中值
  --steps=20000 \                                     # 总训练步数
  --batch_size=8                                      # 每步样本数
```

两个 `★` 组合的含义：**"拿着 4B 的预训练大脑（pretrained_path），只允许微调它身上 1.4M 的 LoRA 小零件（peft）"**——这是单卡能跑通 π₀ 微调的关键。

### 5.2 两段式训练：先冒烟，后正式

```bash
# 阶段一：冒烟测试（~12 秒）——验证"能不能跑"
STEPS=200 BATCH_SIZE=1 bash scripts/train_pi0.sh

# 阶段二：正式训练（~57 分钟）——真正"学出来"
rm -rf outputs/pi0_aloha_cube        # 清掉冒烟残留，否则 FileExistsError
BATCH_SIZE=8 bash scripts/train_pi0.sh
```

| | 冒烟测试 | 正式训练 |
|---|---|---|
| 步数 / 批量 | 200 / batch 1 | 20000 / batch 8 |
| 看过的数据 | 0.01 个 epoch | 8 个 epoch |
| 显存（实测） | 9.2GB | 15.3GB |
| 耗时（实测） | 12 秒 | ~57 分钟（5.85 step/s） |
| 目的 | 打通全链路，暴露配置错误 | 学习策略 |

为什么必须先冒烟：训练链路环节多（字段对齐、权重格式、tokenizer、显存、目录），任何一处出错都可能跑半小时才暴露。本项目就是靠冒烟测试在 12 秒内暴露了 paligemma tokenizer 的 HF 超时问题。两档命令走**同一脚本、同一套自检**，保证"冒烟验证的就是正式要跑的"。

### 5.3 训练时内部发生了什么（一步的旅程）

每一个训练步（step），框架做五件事：

```
1. 抽样本   从 20000 帧里随机抽 8 帧（batch_size=8）
2. 前向     每帧的"画面+指令"喂给 π₀，Action Expert 对真实动作加噪后尝试还原
3. 算 loss  还原结果与真实动作的均方误差 = 本步 loss
4. 反向     梯度只流经 LoRA 适配矩阵（其余 4B 参数冻结，不算梯度 → 省显存省时间）
5. 更新     AdamW 优化器按当前学习率微调这 1.4M 参数
```

学习率按 **cosine 带热身** 调度：先线性升到峰值 2.5e-5，再余弦衰减到 2.5e-6。v0.6.2 会按总步数自动缩放（冒烟 200 步时日志显示 `Scaling warmup: 1000 → 6`），无需手动干预。

## 六、阶段 3：读懂训练——监控与结果解读

### 6.1 日志每 1000 步打印一行，每个字段的含义

正式训练日志（`logs/train_*.log`）中的典型一行（本机实测，step 7000）：

```
step:7K smpl:54K ep:136 epch:2.72 loss:0.114 grdn:0.351 lr:1.9e-05
data_s:0.000 prep_s:0.002 updt_s:0.169 step_s:0.172 smp/s:47 mem_gb:15.26
```

| 字段 | 含义 | 怎么判断健康 |
|------|------|--------------|
| `step` | 当前步数 | 进度条对照 |
| `smpl` | 累计处理样本数（step × batch） | — |
| `ep` / `epch` | 已看过的 episode 数 / epoch 数 | 20000 步 × 8 ÷ 20000 帧 = 8 epoch |
| **`loss`** | **flow matching 还原误差（最重要）** | 见 6.2 |
| `grdn` | 梯度范数 | 平稳不爆炸即可；突然飙升可能是坏样本或 lr 过大 |
| `lr` | 当前学习率 | 按调度器先升后降，符合预期 |
| `data_s` / `prep_s` / `updt_s` | 数据加载 / 预处理 / GPU 更新耗时（秒） | `data_s` 应 ≪ `updt_s`，否则 dataloader 是瓶颈 |
| `step_s` / `smp/s` | 单步总耗时 / 每秒样本数 | 实测 0.172s/步、47 样本/秒 |
| `mem_gb` | 显存占用 | batch 8 实测 15.26GB / 32GB，有余量可加 batch |

### 6.2 loss 多少算正常（本任务实测轨迹）

| 阶段 | loss | 说明 |
|------|------|------|
| 训练开始 | ~1.0 | flow matching 的初始误差就在 1 附近，**不是没初始化好** |
| 冒烟 200 步后 | ~0.99 | 只看了 0.01 个 epoch，几乎没学——冒烟本来就不求学习 |
| 正式训练 step 7K | ~0.11 | 快速下降期，模型已掌握大致轨迹 |
| 训练收敛后 | 0.05~0.1 区间震荡 | 平台期，继续训收益递减 |

**解读要点**：

- loss 是"还原动作的误差"，不是"任务成功率"——loss 低不等于 rollout 一定成功，最终以第七节评估为准；
- loss 长期不降：检查 rename_map 是否漏配、pretrained_path 是否真的加载了（日志应有 `Loading model from: ...` 与 `Remapped 777 state dict keys`）；
- loss 变 NaN 或剧烈震荡：降学习率或 batch 太小。

### 6.3 训练产物：checkpoint 里有什么

训练按 `save_freq`（默认每 20000 步，即结束时）保存到：

```
outputs/pi0_aloha_cube/
├── train_config.json                  # 本次训练的完整配置快照（resume 用它）
└── checkpoints/
    ├── 020000/                        # 按步数命名的中间快照
    │   ├── pretrained_model/          # ★ 推理用这个：权重 + config + tokenizer
    │   └── optimizer_param_groups.safetensors  # 优化器状态（只为续训服务）
    └── last/pretrained_model/         # ★ 最新快照，lerobot-eval 直接用它
```

初学者只需记住：**推理/评估永远指向 `checkpoints/last/pretrained_model`**；中断续训用 `--resume=true --config_path=.../train_config.json`（部署指南 5.2 尾注）。

## 七、阶段 4：仿真评估——让模型独立考试

### 7.1 什么是 rollout

训练时模型是"开卷"：给它真实画面，问它动作，再对照标准答案算 loss。rollout 是"闭卷考试"：

```
仿真环境开机 → 模型看到第一帧画面 → 输出 50 步动作 → 机械臂执行
→ 环境推进物理仿真，给出新画面 → 模型再看再输出 → ……循环最多 400 帧
→ 判定：方块是否成功交到右臂并放下（成功/失败）
```

评估指标就一个：**25 轮里成功几轮 → 成功率**。这个任务经过 20000 步 LoRA 微调，预期成功率可达较高水平；若明显偏低，参考 7.4 的排查思路。

### 7.2 评估命令

```bash
lerobot-eval \
  --policy.path=outputs/pi0_aloha_cube/checkpoints/last/pretrained_model \  # ★ 加载训好的 checkpoint
  --env.type=aloha \                 # 环境类型（v0.6.2 写法；旧版教程的 --env.name 已废除）
  --env.task=AlohaTransferCube-v0 \  # 具体任务
  --eval.n_episodes=25               # 考 25 轮
```

逐参数说明：

- `--policy.path`：直接加载 checkpoint（注意它和训练时的 `--policy.type + --policy.pretrained_path` **互斥**——训练是"从基座搭模型"，评估是"直接打开成品"，两种装载方式只能选一种）；
- `--env.type=aloha`：选择 `gym-aloha` 环境（本机已装，冒烟测试 351 FPS 见部署指南 6.4）；
- `--eval.n_episodes=25`：轮数。25 是常用折中：置信区间够窄、耗时可接受（每轮约几十秒仿真时间）。

可选：加 `--eval.recording` 录制每轮视频，方便肉眼复盘失败原因。

### 7.3 看懂评估结果

输出会汇总 `success_rate`（0~1）。对照 loss 一起看：

| loss | 成功率 | 解读 |
|------|--------|------|
| 高（>0.5） | 低 | 没学会：检查训练是否真正完成、数据与 rename_map |
| 低（<0.1） | 低 | "会做动作但考不过"：多为泛化/执行问题，见 7.4 |
| 低 | 高 | ✅ 目标状态 |

### 7.4 失败怎么分析（初学者排查清单）

1. **看视频**：开 `--eval.recording`，肉眼观察失败模式——是抓不起（定位差）、递不过去（轨迹差）还是接不住（时序差）；
2. **动作抖动**：机械臂高频颤抖通常是 chunk 边界衔接问题，确认用的是 π₀ 默认 chunk 执行逻辑（部署指南排错表"rollout 动作抖动"条目）；
3. **加训**：成功率边缘（如 40-60%）时，用 `--resume=true` 续训或增大 steps；
4. **数据曝光量**：成功率不理想时先算 epoch（见 7.5）——本任务 50 段演示是官方标准量，通常缺的不是数据本身，而是模型把数据看了多少遍。

### 7.5 案例：20k 步后成功率 0%——如何诊断与“加量重训”

本节以本机首次实测（2026-08-18）为例，演示“看结果 → 找证据 → 调参数”的完整思路。

**实测结果**：20000 步（batch 2）训完，loss 0.996→0.09 进入平台；25 轮评估成功率 0%，但 4 轮拿到部分奖励（29/62/3/18 分，单步最高奖励 2.0）——不是完全没学，而是“差最后一段”。

**视频诊断**：抽部分奖励最高一轮的帧可见，右臂已会“接近方块 → 夹起抬起 → 双臂中央会合尝试交接”，但方块在交接时掉回桌面、未完成放置。即**粗行为链已学会，缺的是精细协调精度**（对照 7.4 的“递不过去/接不住”）。

**关键问题：是数据不够吗？** 不是。这份 50 段演示与 openpi 官方 `pi0_aloha_sim` 配置用的是同一数据集，官方配方能训成。真正的差距在“模型把这份数据看了多少遍”：

```
epoch = steps × batch_size ÷ 数据帧数（20,000）
```

| 配置 | steps | batch | 看过样本数 | ≈ epoch |
|------|-------|-------|-----------|---------|
| 官方 openpi `pi0_aloha_sim` | 20,000 | 32（默认） | 640,000 | **32** |
| 本机首跑 | 20,000 | 2 | 40,000 | **2** |
| 本次重训 | 60,000 | 4 | 240,000 | **12** |

官方开 batch 32 是多卡/TPU 的算力配置；单卡 5090 32GB 装不下（本机实测 batch 8 ≈ 15.3GB 显存）。单机路线只能**用 steps 补 batch 的缺口**——这就是“加量重训”的准确含义：**不加新数据，加的是同一份数据上的曝光量**。模仿学习的规律：粗结构几遍就收敛，精细协调要几十遍打磨，正好对应视频里“前两段会、最后一段掉链子”的现象。

**为什么调这两个参数、不动别的**（证据驱动、最小改动）：

| 候选参数 | 决策 | 证据 |
|----------|------|------|
| steps ↑ | ✅ 调 | epoch 缺口 16 倍，最明确的差距 |
| batch 2→4 | ✅ 调 | 梯度噪声更小，flow matching 学精细分布更稳；显存有余量 |
| 学习率 | ❌ 不动 | loss 0.996→0.09 平滑收敛，无发散/停滞迹象 |
| LoRA r 16→32 | ❌ 先不动 | loss 平台与 batch 8 跑法同量级（0.09 vs 0.114），容量不是瓶颈 |
| 加数据 | ❌ 不动 | 官方标准集；“加数据”是真机采集场景的话题 |

**执行**（预计 4-5 小时；20k@b2 实测 57 分钟，步数 ×3、单步耗时约 ×1.5-2）：

```bash
# 1. 归档旧结果（train 脚本对已存在的 output_dir 会报 FileExistsError；eval 视频也会被覆盖）
mv outputs/pi0_aloha_cube      outputs/pi0_aloha_cube_20k_b2
mv outputs/eval_pi0_aloha_cube outputs/eval_pi0_aloha_cube_20k_b2

# 2. 加量重训（≈12 epoch）
STEPS=60000 BATCH_SIZE=4 bash scripts/train_pi0.sh

# 3. 重跑 25 轮验收
bash scripts/eval_pi0.sh
```

**风控**：小数据 + 多 epoch 有过拟合风险（LoRA 本身有一定正则作用），对策是对比中间 checkpoint（如 040000 vs last）的评估成功率，选最优而非盲目选 last；若 12 epoch 后仍“抓起但掉落”，再逼近官方样本量（如 `STEPS=100000 BATCH_SIZE=4` = 20 epoch，overnight 跑一晚）。

## 八、常见问题（初学者版）

| 问题 | 回答 |
|------|------|
| 为什么训练这么快（23 step/s）？ | LoRA 只训 1.4M/4B 参数，反向传播不经过冻结权重；batch 越小越快。快≠学会，看 loss 与 rollout |
| 冒烟测试 loss 0.99 是不是失败了？ | 不是。冒烟只为验证流程，0.01 个 epoch 本来就学不到东西 |
| 训练一定要 GPU 吗？ | 4B 模型 CPU 上一步要几分钟，实际上只能 GPU。本机 5090 实测见上文 |
| 能换别的任务吗？ | 能。`gym-aloha` 还有其他任务（如 `AlohaInsertion-v0`），换 `--env.task` 与对应数据集即可，流程不变 |
| 能用自己的数据吗？ | 能。用 LeRobot 的数据格式（parquet + mp4 + meta/info.json）录制整理后，改 `--dataset.root`；注意相机键名与基座的对齐问题（rename_map） |
| 中断了怎么办？ | `lerobot-train --resume=true --config_path=outputs/pi0_aloha_cube/train_config.json` |
| 报错从哪里查？ | 先看本教程对应章节，再查部署指南第八节排错速查表（含全部实测踩坑） |

## 九、上传模型到 ModelScope

训练完成后，checkpoint 保存在 `outputs/pi0_aloha_cube/checkpoints/<step>/pretrained_model/`。国内环境连不上 HuggingFace，推荐上传到 [ModelScope](https://modelscope.cn)（阿里达摩院开源模型社区，国内访问快、生态全）。

### 9.1 安装与登录

```bash
pip install modelscope

# 去 https://modelscope.cn/my/myaccesstoken 获取 SDK 令牌
ms login --token YOUR_MODELSCOPE_TOKEN
```

### 9.2 创建模型仓库

```bash
# 在 ModelScope 上创建公开模型仓库（首次上传前必须创建）
ms create zgrxmm/pi0_aloha_cube
```

> 将 `zgrxmm` 替换为你的 ModelScope 用户名。如果提示仓库已存在，跳过此步。

### 9.3 上传 checkpoint

```bash
# 上传 160000 step 的 pretrained_model 目录
ms upload zgrxmm/pi0_aloha_cube \
  outputs/pi0_aloha_cube/checkpoints/160000/pretrained_model
```

`ms upload` 的语法是**位置参数**（不是 `--model_id` / `--local_dir`）：

```
ms upload <repo_id> <local_path> [path_in_repo]
```

上传完成后，在 `https://modelscope.cn/models/zgrxmm/pi0_aloha_cube` 即可看到模型文件。

### 9.4 备选：纯本地打包分享

如果只是给同事传文件，不用上传到平台：

```bash
cd outputs/pi0_aloha_cube/checkpoints
tar czf pi0_aloha_cube_160k.tar.gz 160000/pretrained_model/
# 然后用网盘 / oss / scp 分享
```
