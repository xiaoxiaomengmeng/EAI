# PI0 理论与实践全链路实录：从模型原理到本地训练评估

> 本文记录在本地台式机上完成 PI0 模型「数据准备 → 模型下载 → LoRA 训练 → 评估测试 → 失败分析 → 全链路跑通」的完整过程，理论和实践相结合。

---

## 一、PI0 模型是什么

PI0（Open π₀）是 Physical Intelligence 发布的视觉-语言-动作（VLA）模型。它的核心思想是：**把机器人控制建模成一个 Flow Matching（流匹配）问题**——从纯高斯噪声出发，通过学习到的速度场积分去噪，最终生成一段连续的动作序列。

### 1.1 PI0 架构速览

PI0 由两个 Transformer 组成「双流融合」结构：

```
┌──────────────── 前缀（理解场景）────────────────┐  ┌── 后缀（生成动作）──┐
│  顶视图像 → SigLIP ViT → 256 个视觉 token        │  │ 关节状态 → 1 token   │
│  任务文本 → Gemma Embedding → 48 个语言 token     │  │ 噪声动作 → 50 token  │
│  共 304 token, D=2048                             │  │ 时间嵌入 → 融合      │
└───────────────────────────────────────────────────┘  └─────────────────────┘
                         ↓ 拼接 355 token ↓
          ┌──────────────────────────────────────────────┐
          │  PaliGemma 2B + Gemma Expert 300M            │
          │  18 层双流 Transformer 融合                   │
          │  视觉/语言/状态/动作在同一个 attention 空间    │
          └──────────────────────────────────────────────┘
                         ↓ 取最后 50 个 action token ↓
                   action_out_proj → 14D 动作 × 50 步
```

- **PaliGemma 2B**（冻结）：负责视觉编码（SigLIP）+ 语言理解（Gemma），把图像和任务文本变成统一维度的 token
- **Gemma Expert 300M**（微调）：负责动作时序预测，把理解到的场景信息翻译成 14D 关节运动指令
- **Flow Matching**：训练时让模型预测「从噪声到真实动作的速度方向」，推理时从纯噪声出发积分 10 步得到动作

### 1.2 PI0 与 OpenVLA 的最大区别

| 维度 | OpenVLA | PI0 |
|---|---|---|
| **动作生成方式** | 自回归：逐 token 预测离散动作 | **Flow Matching**：从连续噪声积分去噪得到连续动作 |
| **动作空间** | 离散化（把关节角度分箱成 256 个 bin） | **连续空间**（直接输出 float 关节角度） |
| **时序预测** | 一次只预测 1 步动作 | **一次预测 50 步动作 chunk**（1 秒@50fps） |
| **误差累积** | 每步都闭环，容易雪崩 | chunk 缓存减少闭环频率，但 chunk 内不纠偏 |
| **模型结构** | 单一 VLM（Gemma 2B）直接输出动作 token | **双流**：PaliGemma 理解 + Gemma Expert 预测，分工明确 |
| **微调策略** | 通常全参或 LoRA 微调同一模型 | 可冻结 PaliGemma 只训 Expert，梯度信号更纯净 |

**一句话总结**：OpenVLA 像「一个大脑同时看和做」，PI0 像「眼睛和大脑分工——PaliGemma 负责理解场景，Gemma Expert 专门负责生成动作」，而且用连续 Flow Matching 替代了离散自回归，天生更适合精细的连续控制任务。

## 二、本地实践：数据与模型准备

### 2.1 数据集

在本地下载了 ALOHA 仿真数据集 `aloha_sim_transfer_cube_human`：

```json
{
    "total_episodes": 50,      // 50 条专家演示
    "total_frames": 20000,     // 每条 400 帧 × 50 条
    "total_tasks": 1,          // 单任务：TransferCube（右臂抓方块递给左臂）
    "fps": 50                  // 采集频率 50Hz
}
```

数据集每帧包含：
- **顶视 RGB 图像**（480×640×3，存为 mp4 视频流）
- **关节状态**（14D float32：左臂 7 关节 + 右臂 7 关节，含夹爪开合）
- **动作标注**（14D float32：下一时刻的目标关节角度）
- **任务描述**（恒定字符串："Pick up the cube with the right arm and transfer it to the left arm."）

50 条演示 × 400 帧 = 20,000 帧训练数据。这是 ALOHA 原版论文使用的标准仿真数据集。

### 2.2 模型下载

PI0 基座模型（`pi0_base`）约 14GB（F32 保存），包含：
- PaliGemma 2B（SigLIP ViT + Gemma 语言模型）
- Gemma Expert 300M
- state/action/time 投影层

由于 HuggingFace 在国内不可直接访问，tokenizer 从 ModelScope 下载后注入 HF 离线缓存，训练时设置 `HF_HUB_OFFLINE=1` 跳过所有网络请求。

## 三、LoRA 训练过程

### 3.1 训练配置

采用 LoRA（Low-Rank Adaptation）参数高效微调：

```bash
# 关键训练参数
STEPS=160000          # 160k 步
BATCH_SIZE=4          # 5090 32GB 可用 batch 4
--peft.method_type=LORA
--peft.r=32           # LoRA 秩 32，可训参数 ~2.8M（全参 2.3B 的 0.12%）
--policy.dtype=bfloat16
--policy.gradient_checkpointing=false  # LoRA 显存充裕不需要
```

**epoch 计算**：160,000 步 × batch 4 ÷ 20,000 帧 = **32 epoch**，对齐官方 openpi 的曝光量。

### 3.2 Loss 曲线

![训练 Loss 曲线](../logs/loss_curve.png)

从 loss 曲线可以看出：
- **0-20k 步**：warmup + 快速下降阶段，loss 从 ~0.15 降到 ~0.09
- **20k-60k 步**：主要下降阶段，loss 从 ~0.09 降到 ~0.077，**约 60k 步基本收敛**
- **60k-160k 步**：精细打磨阶段，lr 已从 2.5e-5 cosine decay 到 2.5e-6，loss 在 0.076-0.085 之间波动，变化极小

这说明：**粗结构（右臂接近方块）在 60k 步就已学会，后续 100k 步只是边际优化**。这也和评估结果一致——策略能抓起方块（粗结构）但无法完成交接（精细协调）。

### 3.3 训练日志摘录

```
step: 60K  smpl:240K ep:1K epch:12.00 loss:0.077 grdn:0.596 lr:2.5e-06    ← 基本收敛
step:160K  smpl:640K ep:2K epch:32.00 loss:0.076 grdn:0.589 lr:2.5e-06    ← 训练结束
```

- `smpl`：已采样样本数（160k × 4 = 640k）
- `epch`：epoch 数（640k ÷ 20k = 32）
- `loss`：Flow Matching MSE loss（预测速度场 vs GT 速度场）
- `grdn`：梯度范数（被 clip 到 1.0 以内，训练稳定无爆炸）
- `lr`：学习率（30k 步后已 decay 到 2.5e-6 低位打磨区）

## 四、评估测试

### 4.1 评估方式

评估在 MuJoCo 仿真环境中进行，与训练完全独立：

- **环境**：`gym_aloha/AlohaTransferCube-v0`，方块初始位置**随机**摆放
- **每轮**：400 步（8 秒@50fps），策略观察当前帧 → 预测 50 步动作 → 执行第 1 步 → 循环
- **统计**：25 轮（或 50 轮）的累积 reward、最高 reward、成功率

**Reward 阶梯**：

| reward | 条件 | 含义 |
|---|---|---|
| 0 | 无事发生 | 策略还没碰到方块 |
| 1 | 右爪接触方块 | 第一步：接近成功 |
| 2 | 右爪抓住方块并举离桌面 | 第二步：抓取成功 |
| 3 | 左爪接触方块 | 第三步：交接开始 |
| 4 | 左爪抓住方块 + 离桌面 | **最终成功**（success=True） |

### 4.2 评估结果

25 轮评估汇总：

```json
{
  "avg_sum_reward": 35.8,     // 平均每轮累积 reward
  "avg_max_reward": 0.52,     // 平均每轮达到的最高 reward 级位
  "pc_success": 0.0           // 成功率 0%（无任何一轮达到 reward=4）
}
```

逐轮 reward 分布：

```
max_reward=0（没碰方块）:  15/25 轮 = 60%
max_reward=1（碰了没抓住）:  1/25 轮 = 4%
max_reward=2（抓住并举起）:  9/25 轮 = 36%
max_reward=3（左爪碰方块）:  0/25 轮 = 0%  ← 从未到达
max_reward=4（完全成功）:   0/25 轮 = 0%
```

### 4.3 视频演示

评估过程自动录制了每轮的 rollout 视频。以下选取两轮典型案例：

#### 失败案例：episode 0（max_reward=0）

```

```

策略在 400 步内未能接近方块。从视频可以看到：右臂朝方块方向移动了一段距离，但轨迹偏差较大，最终在方块旁边停下，未触碰到方块。这是 60% 评估轮次的典型表现——策略「知道要往方块方向走」但「定位不够精确」。

#### 最佳案例：episode 2（max_reward=2, sum_reward=436）

## 五、为什么成功率为 0%

虽然没有一轮完全成功，但 36% 的轮次能到 reward=2（抓起方块），说明策略已经学会了右臂抓取。成功率 0% 的原因有三层：

### 5.1 LoRA 容量限制（主要原因）

LoRA r=32 只在 Gemma Expert 的 Q/V 投影矩阵上加了 2.8M 低秩参数。Expert 的 FFN（前馈网络，~180M 参数）完全冻结——而 FFN 恰恰是「从理解到决策」的非线性映射核心。

> 类比：LoRA 调整了「该看哪里」（attention Q/V），但没动「看完怎么决策」（FFN）。面对随机方块位置需要泛化时，FFN 不够用。

### 5.2 数据覆盖度不足

训练数据的 50 条 demo 本身也是随机摆放方块后采集的（并非 50 个固定位置），但 50 个随机样本对连续空间的覆盖仍然非常稀疏——方块可能出现在桌面任意位置，50 个采样点远不足以让模型学会完整的位置→轨迹连续映射。LoRA 2.8M 可训参数倾向于「记住这 50 个位置该怎么走」而非「学会任意位置的通用策略」，导致评估时遇到训练集 50 个采样点附近之外的位置就失效。

### 5.3 Behavior Cloning 的误差累积

训练时用教师强制（每帧都喂 GT 动作），评估时闭环执行（模型自己的预测作为下一步输入）。前一步的偏差会被模型当作新的「未见状态」处理，误差逐层放大。PI0 的 action chunking（一次预测 50 步）能缓解但无法根除这个问题。

## 六、全链路跑通的意义

虽然成功率为 0%，但**完整的训练-评估闭环已经跑通**：

```
数据集下载 → 基座模型加载 → LoRA 微调 160k 步 → loss 收敛
→ MuJoCo 仿真评估 25 轮 → 36% 抓起方块 → 0% 完成交接
→ 失败分析 → 定位到 LoRA 容量瓶颈 → 规划全参微调方案
```

这条全链路的意义在于：

1. **验证了流程正确性**：数据格式、processor 流水线、模型加载、训练循环、评估环境全部对接无误
2. **定位了性能瓶颈**：不是配置错误或代码 bug 导致 0%，而是 LoRA 容量不足以学习双臂交接的精细协调
3. **给出了明确的优化方向**：从 LoRA r=32（2.8M）升级到只训 Expert 全参（350M，125 倍参数），显存仅多 ~2GB，但 FFN 可训后能学习连续位置→动作映射

### 下一步优化方案 → 已执行并验证

针对 LoRA 0% 成功率的根因（FFN 冻结），采用「冻结 PaliGemma 2.4B、只训 Gemma Expert 300M 全参」的方案：
昨天 LoRA r=32 评估成功率 0%，定位到瓶颈是 LoRA 容量不足（FFN 冻结）。昨晚启动 Expert 全参微调（冻结 PaliGemma 2.4B，只训 Gemma Expert 300M 全参，350M 可训参数，是 LoRA 的 125 倍），训练 200k 步（40 epoch），耗时约 10 小时，loss 从 0.076 降至 0.034（降 55%）。

今天上午评估 25 轮 rollout，**成功率从 0% 提升到 16%**——4 轮（episode 16/17/18/21）完整完成双臂交接，左臂成功接住方块。avg_sum_reward 从 35.8 提升到 46.0，avg_max_reward 从 0.52 提升到 0.8。验证了昨天的分析：FFN 解冻后，策略获得了足够的非线性映射能力来学习双臂交接的精细协调。
```bash
# 只训 Gemma Expert 300M 全参（冻结 PaliGemma 2.4B）
# 可训参数从 2.8M → 350M（125 倍），显存 ~11GB，5090 充裕
WANDB_ENABLE=true TRAIN_EXPERT_ONLY=true BATCH_SIZE=4 \
  bash scripts/train_pi0_full.sh
```

**训练结果**：

| 最终 loss | 0.076 | 0.034 | -55% |

## 总结

今天实践了 PI0 模型从理论到本地仿真实践的全链路过程。首先，PI0 是 Physical Intelligence 发布的 VLA 模型。它的核心思想是：把机器人控制建模成一个 Flow Matching 问题——从纯高斯噪声出发，通过学习到的速度场积分去噪，最终生成一段连续的动作序列。PI0 的基座 PaliGemma 预训练于大规模图文对数据，具备天然的视觉语言泛化能力。它采用双流架构，PaliGemma 负责视觉语言理解，Gemma Expert 负责动作生成。我在台式机上使用 50 条 ALOHA 仿真演示数据，通过 LoRA r=32 微调 160k 步，loss 在 60k 步基本收敛，共训了 4 个半小时。晚上评估了 25 轮 rollout，36% 的轮次右臂成功抓起方块，但无一完成双臂交接。初步分析指向 LoRA 容量不足、50 条随机样本对连续位置的覆盖度稀疏、以及 BC 固有的闭环误差累积。尽管未达到成功标准，但训练-评估全链路已跑通，流程正确性得到验证，下一步优化方向：冻结 PaliGemma 只训 Expert 全参，以获得足够的非线性映射能力学习双臂交接的精细协调。
